## Overview

The hosted board shows card images from the playmat's own copy in the shared store, served from the playmat's own public image address, instead of loading every image from the card source. Images not yet copied still show straight away and are copied in the background.

## Requirements

- [ ] **Card images cached**
  The system must keep a copy of every card image the board shows from the card source in the shared store. The hosted board must load those images from the shared store's public delivery address, not from the card source.
- [ ] **Images without a copy still shown**
  When an image has no copy in the shared store yet, the board must still show it, loading it from the card source. The system must then add the copy without the player waiting for it.
- [ ] **Images load as today without the shared store**
  Without the shared store configured, the board must load images from the card source as today, and the system must not try to copy them.
- [ ] **Fallback when a copy cannot load**
  If an image cannot be loaded from the shared store's address, the board must fall back to the card source and still show it.
- [ ] **Copies kept until cleared**
  An image copy must be kept until an admin clears it. A card whose artwork arrives later gets its own new copy.

## Constraints

- The shared store must be DigitalOcean Spaces.
- It must run on the existing DigitalOcean App Platform deployment: one instance with no persistent volume, where local disk is wiped on every deploy or restart. Settings and credentials must arrive as App Platform environment variables, with the credentials as encrypted secrets.
- Cached card images must be copies of the card source's own images. No other image source may be used.

## Acceptance Criteria

- [ ] **Hosted images from the shared store**
  On the hosted board, every card image that loads comes from the shared store's public delivery address, apart from images whose copy is still being added. Images with a copy make no requests to the card source's image host.
- [ ] **Missing image filled in**
  An image with no copy in the shared store still shows on the board on first view, and has a copy in the shared store within 60 seconds. Later views load it from the shared store.
- [ ] **No shared store, images as today**
  Started without shared store settings, the board loads every image from the card source, and nothing is copied.
- [ ] **Broken copy falls back**
  With the shared store's image address unreachable, every card image still shows on the board, loaded from the card source.

## Technical Approach

- Serve the board's images through the Spaces CDN.
- Expect this risk: Mirroring card art to a public CDN carries the same fan-site-tolerance caveat as the card source itself.
