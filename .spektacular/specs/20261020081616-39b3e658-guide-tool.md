# Feature: 20261020081616-39b3e658-guide-tool

## Overview

Any assistant connected to the tcgreplay playmat learns its coaching workflows straight from the playmat itself. Those are importing a game, guessing the opponent's deck, reviewing a game, replaying past mistakes as drills, the pre-move checklist and numbers drills. Nothing has to be installed or uploaded on the player's side.

Today those workflows have to be copied into each assistant separately, some players have to upload them by hand, and the copies go stale whenever the playmat changes. Serving them from the playmat means every player gets the same, current coaching on every client the moment they connect.

## Requirements

- [ ] **Assistants can list the guides**
  An assistant connected to the playmat can ask for the list of guides and get, for each one, its name and a one-line description of when to use it.
- [ ] **Assistants can read a guide by name**
  An assistant can ask for one guide by name and get its full text. Asking for a name that doesn't exist returns an error that lists the valid names.
- [ ] **The six coaching workflows are guides**
  The guides cover the same six workflows the skills do today, with the same substance: importing a game, building the opponent's likely deck, reviewing a game, replay drills, the pre-move checklist and numbers drills.
- [ ] **Guides refer to each other by guide name**
  Wherever one workflow sends the assistant to another ("offer a review first"), it names the other guide so the assistant can fetch it, never a skill.
- [ ] **Connecting is enough to know the guides exist**
  The instructions the playmat sends every connecting assistant name each guide with a one-line "use when", and say to read the guide before starting that workflow.
- [ ] **Guides can be picked directly where clients allow it**
  In clients that let users pick starting instructions a server offers, each guide can be picked directly and gives the same text as reading it.
- [ ] **Hosted and desktop serve the same guides**
  The hosted playmat and the desktop playmat offer the same guides with the same text.
- [ ] **Skills are no longer shipped**
  The playmat no longer delivers its coaching workflows as skills: it never installs, copies or refers to them.
- [ ] **The install command is removed**
  The playmat no longer has an install command. Registering the playmat with a client is done with the client's own tools, and the playmat's help no longer mentions install or skills.
- [ ] **Guide text follows the existing conventions**
  Guides name no particular assistant or player. They name turns the way the playmat counts them, where turn N is both players' Nth turns, always with whose turn it is (for example "turn 3, p2"). Branch names they prescribe include both the turn and the player's seat (for example `review-t3-p2`), and they only refer to tools the playmat has.

## Constraints

- **Nothing to install.** An assistant must be able to use the guides with nothing installed on the player's side, just a connection to the playmat. This is the goal of the change.
- **Must work in every client.** Reading guides must work in any client that can call the playmat's tools. Prompts are an extra for clients that support them, never the only way to reach a guide. Support for server prompts varies between clients.
- **Short instructions.** The instructions sent on connect must stay short, about one line per guide, because clients send them to the model every turn. The full guide text is only sent when asked for.
- **Spektacular's own skills stay.** The project's Spektacular skills, and the links to them that this repo's tooling uses, must keep working. Only the tcg coaching skills are removed.
- **Guides ship with the playmat.** Guides must be part of the playmat version they describe, so their text always matches that version's tools; they must not be fetched from anywhere else at runtime.
- **Conventions are enforced automatically.** The guide conventions must be checked automatically, so a guide that breaks one is caught before release.
- **Nothing on players' machines is touched.** Skill copies already installed or uploaded stay as they are; the player deletes them by hand.

## Acceptance Criteria

- [ ] **Listing the guides**
  A freshly connected assistant that asks for the guides gets six entries named `import-game`, `opponent-deck`, `review-game`, `replay-drill`, `before-you-move` and `numbers-drill`. Each has a name and a one-line "use when".
- [ ] **Reading a guide**
  Asking for `review-game` returns its full text, including how to find decision points and how to record findings. Asking for "tcg-review" (a name that doesn't exist) returns an error listing the six valid names.
- [ ] **Same workflows as before**
  Every rule the six skills give today appears in the matching guide, for example "ask before judging", "put the board where you are talking" and recording findings on the timeline. A side-by-side read finds no step dropped.
- [ ] **Cross-references resolve**
  Every other workflow a guide mentions is named by a guide name that, asked for, returns that guide. No guide mentions a skill.
- [ ] **Instructions announce the guides**
  The instructions a new connection receives list all six guide names, each with its "use when" line, and tell the assistant to read the guide before starting that workflow.
- [ ] **Prompts in a supporting client**
  In Claude Code connected to the playmat, the six guides appear as prompts. Choosing the review prompt gives the same text the review guide returns.
- [ ] **Hosted matches desktop**
  Listing the guides and reading each one gives identical results on the hosted playmat and on a desktop playmat built from the same version.
- [ ] **No skills left**
  A connected assistant is never offered or pointed to a tcg skill by the playmat, and no released playmat installs or copies skill files.
- [ ] **Install is gone**
  Running the playmat's install command fails as an unknown command, and the playmat's help text doesn't mention install or skills.
- [ ] **Conventions hold in every guide**
  No guide contains "Claude" or "Nic ", tells the assistant to translate turn numbers, uses a turn branch name without the seat, or names a tool the playmat doesn't have.

## Technical Approach

- Serve the guides from text compiled into the playmat binary, as the skills are today.
- Offer one tool for listing and reading guides; also publish the same text as server prompts.
- Carry the existing skill text over largely unchanged, swapping skill names for guide names; the skills' own trigger descriptions are the natural source for each guide's one-line "use when".
- Move the existing text checks that guard the skills over to the guides, so they run with the test suite.

## Success Metrics

- In a fresh claude.ai conversation with only the playmat connected and no skills uploaded, asking to import and review a game leads the assistant to read the matching guides and run the workflow without the player pointing it at them.
- After the change, a playmat update that changes a workflow reaches every client on its next connection, with zero manual re-installs or re-uploads.

## Non-Goals

- Rewriting, merging or splitting the six workflows.
- Showing guides to players on the playmat (for example a help page); guides are for the connected assistant.
- Pointing the assistant at the next guide from inside tool results (for example the import result suggesting a review).
