## Overview

A small public website for tcgreplay that a Pokémon TCG Live player can open from a shared link and, within a few minutes, understand what the playmat does, connect it to the AI assistant they already use (Claude or ChatGPT), and start reviewing their own games. Today the only explanation is a developer-facing README, which makes the tool hard to share. The home page shows the playmat in action with a short animation of a game being replayed and coached, and the rest of the site is a plain how-to guide: connecting, importing a game, reviewing it, drills, playing a game, what to say to the assistant, the hosted service's limits, privacy, and a clear note that this is an unofficial fan project.

## Requirements

- [ ] **Home page explains the tool at a glance**
  Visitors to the home page see, without scrolling on a laptop screen, what tcgreplay is in one sentence, an animation of the playmat in action, and a clear way to get started.
- [ ] **Home page animation shows the core loop**
  The home page animation shows a game being brought onto the playmat from a battle log, coached by an assistant, rewound to a decision and replayed with a better line. It loops, plays without the visitor doing anything, and does not need the hosted playmat to be reachable.
- [ ] **Animation respects reduced motion**
  Visitors whose device asks for reduced motion see a still image of the playmat in place of the animation, with the same message.
- [ ] **Connecting from each assistant**
  Users can follow step-by-step instructions to connect the hosted playmat from claude.ai, ChatGPT and Claude Code, each ending with how to check the connection works.
- [ ] **Running it on the desktop**
  Users can follow instructions to install the playmat and use it with the Claude desktop app, including where the board opens.
- [ ] **Signing in and opening the board**
  Users can read what to expect when the assistant first asks them to sign in with Google, and how to open the board link the assistant gives them.
- [ ] **Importing a game**
  Users can learn how to import a TCG Live battle log together with their decklist, including where to copy each from in TCG Live and how to tell whether the import was complete.
- [ ] **Reviewing, rewinding and drills**
  Users can learn how to review an imported game, fill in the opponent's likely deck, rewind to a decision and try another line, and practise with each kind of drill the playmat offers.
- [ ] **Playing a game**
  Users can learn how to start and play a game against the assistant on the board.
- [ ] **Covers every coaching workflow**
  The site describes every coaching workflow the playmat offers at the time of publishing.
- [ ] **Example prompts for every workflow**
  Every workflow the site describes comes with at least one example prompt the user can copy.
- [ ] **A ready-made example game**
  Users can copy a complete example battle log and its decklist from the site to try the playmat without a game of their own. The opponent's player name in it is replaced with a placeholder.
- [ ] **Hosted service limits are stated**
  The site states what the hosted playmat keeps and for how long, that games are lost when idle or when the service is updated and how to keep a record, and that the number of players served at once and requests per minute are limited. Where the hosted playmat may be full, the site points to running it on the desktop instead.
- [ ] **Privacy page**
  The site has a privacy page, at its own stable address, saying what the hosted playmat collects when a user signs in and plays, how long it keeps it, and what it never collects.
- [ ] **Unofficial fan project notice**
  Every page states that tcgreplay is an unofficial fan project, not affiliated with or endorsed by Nintendo, The Pokémon Company, Creatures or Game Freak, and credits TCGdex for card data and images.
- [ ] **Developer pointer**
  The site has a short section for developers that links to the source repository for running it locally and contributing, without duplicating the repository's developer notes.
- [ ] **README points to the site**
  The repository README introduces the project briefly and links to the site for user documentation, so user instructions live in one place.
- [ ] **Works on phones**
  Every page is readable and usable on a phone-width screen without horizontal scrolling, including code and prompt blocks.
- [ ] **Copyable prompts and addresses**
  Users can copy each example prompt, the hosted playmat's address, and the example game with one action.
- [ ] **No tracking**
  The site sets no cookies, loads no analytics, advertising or other resources from third-party hosts, and needs no consent banner.
- [ ] **Published automatically**
  Once a change to the site's content is accepted into the project, it is published to the live site without manual steps.

## Constraints

- The site must be static content only: no user accounts, no server-side logic, and no interactive features beyond the home page animation and copy controls.
- The hosted playmat's MCP endpoint address (`https://tcgreplay.demo.gs/mcp`) must not change: connectors people have already added in claude.ai, ChatGPT and Claude Code point at it. The board moves from `/` to `/board` so the site's home page can take the bare address; board links already given in past chats stop working (the user accepted this on 2026-11-06).
- The site's home page and privacy page must be at addresses Google accepts on the hosted playmat's OAuth consent screen (Google requires both for an app offered to the public, on a domain the owner can verify). The site is served at `https://tcgreplay.demo.gs` itself (home at `/`, privacy at `/privacy`), on the domain the consent screen already uses.
- The site and its animation must not reproduce official Pokémon card artwork or the Pokémon and Pokémon TCG logos.
- Everything the site says about the playmat (assistants supported, coaching workflows, limits) must match the playmat as it behaves at the time of publishing.

## Acceptance Criteria

- [ ] **Pitch, animation and start link above the fold**
  On a 1366×768 browser window, the home page shows the one-sentence description, the animation and a "Get started" link without scrolling; following the link opens the connecting instructions.
- [ ] **Animation shows the loop offline**
  With the hosted playmat unreachable (blocked in the browser), the home page animation still plays, loops, and shows in order: a battle log arriving, the board filling with the game, a coaching message, a rewind to an earlier turn, and a different line being played.
- [ ] **Reduced motion shows a still**
  With the operating system's reduced-motion setting on, the home page shows a still image of the playmat where the animation would be, and nothing on the page moves.
- [ ] **Each assistant's instructions lead to a working connection**
  A person who has never used tcgreplay, following only the site's instructions for claude.ai, for ChatGPT and for Claude Code in turn, gets the assistant to confirm it can reach the playmat in each (for example by listing what it can do), and the instructions say how to check this.
- [ ] **Desktop instructions open the board**
  Following only the site's desktop instructions on a machine with the prerequisites the site lists, a person installs the playmat, connects the Claude desktop app, starts a game, and opens the board at the address the site gives.
- [ ] **Sign-in and board link explained**
  The site has text, findable from the connecting instructions, describing the Google sign-in prompt and how to open the board link from the assistant's reply.
- [ ] **Import instructions produce a complete import**
  Following the site's import instructions with the site's example game, the assistant reports an import with no problems, and the site says what a complete import looks like and what to do if lines are missing.
- [ ] **Every coaching workflow is covered**
  For each coaching workflow the playmat offers at the time of publishing, the site has a section describing it with at least one example prompt.
- [ ] **Rewinding is explained**
  The site has a section explaining how to rewind an imported game to a chosen turn and play a different line, with an example prompt.
- [ ] **Example game is complete and anonymised**
  The example battle log on the site has every line of the game from setup to the result, contains no real opponent's player name, and imports with its decklist without problems.
- [ ] **Limits match the service**
  The site's stated idle time, users served at once and requests per minute match the hosted playmat's configured limits at the time of publishing. The site also says what the hosted playmat keeps, that games are lost when the service is updated, that a game's record can be kept and imported again, and that the desktop option is there when the hosted playmat is full.
- [ ] **Privacy page is linkable and complete**
  The privacy page has its own stable address, and states what is collected at sign-in, what is kept while playing, how long each is kept, and what is never collected.
- [ ] **Notice on every page**
  Every page of the site shows the unofficial fan project notice naming Nintendo, The Pokémon Company, Creatures and Game Freak, and the TCGdex credit.
- [ ] **Developer section links out**
  The site's developer section links to the source repository and contains no build or test instructions of its own beyond a pointer.
- [ ] **README links to the site**
  The repository README contains a link to the site's home page and to its connecting instructions, and no longer contains the step-by-step connecting instructions itself.
- [ ] **No horizontal scroll on a phone**
  At a 375-pixel-wide viewport, no page scrolls horizontally, and long code, addresses and prompts wrap or scroll within their own box.
- [ ] **One-action copy**
  Each example prompt, the hosted playmat's address and the example game have a copy control; activating it puts exactly that text on the clipboard.
- [ ] **No cookies or third-party requests**
  Loading every page in a fresh browser profile sets no cookies and makes no requests to any host other than the site's own.
- [ ] **Merged changes go live**
  After a change to the site's content is accepted into the project, the live site shows the change within 15 minutes with no manual step.

## Technical Approach

- The site is static, built at build time and served by the hosted playmat at `https://tcgreplay.demo.gs` (decided by the user on 2026-11-06, replacing the earlier GitHub Pages default: Google has rejected github.io pages as unverifiable). It is published by the playmat's existing automatic deploy on a push to main. Every push to main redeploys the playmat and drops in-memory games; the user accepted that for now.
- Prefer writing the docs pages in Markdown so they are easy to keep current, built into plain HTML. Choose the lightest generator that fits; the repository already has a Node toolchain for the board.
- For the home page animation, prefer something lightweight that is drawn or scripted in the page (CSS or SVG animation, or a short muted looping video captured from the real board) over a heavy embedded player. Keep it in the board's own visual style, with the board's card styling or plain stand-ins in place of card artwork, so it reads as the real product.
- The example game can be the corpus game in testdata/logs dated 2026-10-11, a close loss against a Mew ex / Bronzong / Mega Lopunny ex deck, with the Mega Lucario ex v12 decklist in testdata/decks. Both have been shown to import cleanly from ChatGPT.
- The coaching workflows at the time of writing are: import a game, the opponent's likely deck, review a game, replay drill, before-you-move, numbers drill, and play a game.
- Where practical, take tool names, workflow names and service limits from the playmat itself rather than retyping them, so the site stays accurate as the playmat changes.
- Known risk: the hosted playmat serves a small number of players at once, and a widely shared site could fill it.

## Success Metrics

- A player new to tcgreplay, given only the site's link, connects it to their assistant and imports the example game in under 10 minutes, without help, on at least two of three tries with different people.
- The home page loads, including the animation, with its largest content shown in under 2.5 seconds in a Lighthouse audit with mobile emulation (Slow 4G throttling), and its total download is under 1.5 MB.
- Every page scores at least 90 for accessibility and performance in a Lighthouse audit with mobile emulation.

## Non-Goals

- Changes to the playmat beyond serving the site and moving the board to `/board` (its sign-in, limits, tools and board behaviour stay as they are); the site describes them.
- Accounts, comments, a blog, newsletters, search, versioned docs and translations.
- An API reference or contribution guide.
- A separate domain or host for the site (GitHub Pages or otherwise).
- Replacing the project logo (cards with a Poké Ball). The site uses it until the user decides whether it suits a public site.
