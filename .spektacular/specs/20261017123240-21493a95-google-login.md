## Overview

Put Google sign-in in front of the hosted playmat so only people with a Google account can use it, keeping out anonymous traffic and abuse. Adding the playmat as a connector in claude.ai, or opening a board link, asks the user to sign in with Google, and basic limits stop any one account from overloading the server. "Hosted" means the playmat running on the web as set up in the first spec of this epic; "desktop" means Claude Desktop or Claude Code launching it locally, which stays login-free.

## Requirements

- [x] **Sign-in required when hosted**
  Every use of the hosted playmat, through the connector or the board, needs a signed-in Google account. Anonymous requests are refused.
- [x] **Any Google account**
  Any Google account can sign in. There is no allowlist and no restriction by email domain.
- [ ] **Connector sign-in**
  Adding the playmat as a custom connector in claude.ai takes the user through Google sign-in. After that the connector works without further prompts.
- [x] **Board sign-in**
  Opening a board link while signed out asks the user to sign in with Google, then shows the board.
- [x] **Live board guarded**
  The board's live updates and actions are only available to a signed-in user.
- [ ] **Signed in until restart**
  Once signed in, the user is not asked again until the server restarts (a redeploy counts as a restart). After a restart, the connector and the board ask the user to sign in again.
- [x] **Sign out**
  The user can sign out from the board.
- [x] **Per-account request limit**
  The operator can cap how often one account makes requests. Going over it refuses the request with a message naming the limit hit, rather than a generic error.
- [x] **Signed-in user limit**
  The operator can cap how many signed-in users the server serves at once. A new account over the cap is refused with a message saying the server is busy.
- [x] **Operator settings**
  The Google sign-in credentials and the limits are settings, not code.

## Constraints

- Must use Google as the only sign-in provider.
- Must work with claude.ai's sign-in flow for custom connectors.
- Must not require login when running on the desktop.
- Sign-ins must not be stored; they end when the server restarts.
- Must work when hosted on DigitalOcean App Platform behind Cloudflare.
- Sign-in addresses must use the public address setting that the hosted mode already provides.

## Acceptance Criteria

- [x] **Anonymous connector request refused**
  A connector request without sign-in is refused.
- [ ] **Connector flow**
  Adding the connector in claude.ai opens Google sign-in. After signing in, claude.ai lists the tools and a game import through the connector succeeds.
- [ ] **Any account**
  Two different personal Google accounts can each sign in.
- [x] **Board link**
  Opening a board link while signed out goes through Google sign-in and lands on that board.
- [x] **Live board guarded**
  Without signing in, the board receives no live updates and its actions are rejected.
- [x] **Stays signed in**
  After signing in, using the connector and reloading the board over a period with no server restart never asks for sign-in again.
- [ ] **Restart**
  After the server restarts (including a redeploy), both the connector and the board ask the user to sign in again, then work.
- [x] **Sign out**
  After signing out, reloading the board asks the user to sign in.
- [x] **Rate limit**
  An account that goes over the request cap gets a "too many requests" message, while other accounts carry on working.
- [x] **User cap**
  Once the signed-in user cap is reached, a new account gets a "server busy" message.
- [x] **Settings**
  Changing the credentials or limits in settings and restarting takes effect with no rebuild.
- [x] **Desktop**
  The playmat on the desktop still works with no sign-in.

## Technical Approach

- Prefer the playmat acting as its own small sign-in service for claude.ai, handing the actual login to Google, because Google can't play that role for a connector directly.
- Use the official Go MCP library's auth support to protect the connector, if it fits.
- Prefer a standard Google sign-in with a session cookie for the board.
- Risk: claude.ai's exact connector sign-in requirements are not confirmed, for example client registration and how it discovers the sign-in service.
- Risk: it is unknown whether claude.ai asks the user to sign in again by itself after a restart wipes its sign-in, or just shows errors.
- Risk: cookies and redirects through Cloudflare and App Platform (see Constraints) need checking early.
