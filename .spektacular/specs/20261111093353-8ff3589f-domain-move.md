# Feature: 20261111093353-8ff3589f-domain-move

## Overview

The hosted playmat (website, board, assistant connection and sign-in) moves from its borrowed address, tcgreplay.demo.gs, to its own domain, **tcgreplay.app**, which becomes the one address shown and used everywhere. It comes first in the public launch because the ChatGPT listing, the docs and the privacy and terms pages all name the address, and a published ChatGPT plugin can't change it later. Players already using the old address aren't stranded: pages there forward to the new domain, and an assistant still connected to the old one tells the player the playmat has moved and where to reconnect.

## Requirements

- [ ] **One canonical address**
  The website, board, assistant connection and Google sign-in all work at `https://tcgreplay.app`, and every address the playmat hands out while running (board links, sign-in and connection details) names tcgreplay.app.
- [ ] **Players can connect at the new address**
  A player can sign in with Google at tcgreplay.app and connect claude.ai, ChatGPT or Claude Code to `https://tcgreplay.app/mcp`.
- [ ] **Secure, with no www name**
  `tcgreplay.app` is served over HTTPS with a valid certificate, and plain HTTP requests are sent to HTTPS. The playmat has no `www` name: `www.tcgreplay.app` isn't set up and isn't shown anywhere.
- [ ] **Old pages forward**
  Website and board page requests to `tcgreplay.demo.gs` are permanently redirected to the same path and query on `https://tcgreplay.app`.
- [ ] **Old assistant connection explains the move**
  An assistant still connected at `tcgreplay.demo.gs/mcp` doesn't fail with a bare error. The player is told, in the assistant, that the playmat has moved and to reconnect at `https://tcgreplay.app/mcp`.
- [ ] **Old address can be retired without a release**
  The old address keeps forwarding and showing the moved message for as long as the maintainer keeps it configured, and can be removed by configuration alone, without shipping a new version.
- [ ] **Maintainer has the console steps**
  The maintainer has written, ordered steps for the DNS, hosting-domain and Google sign-in changes, each with a way to check that it worked.
- [ ] **No stray old address**
  No page, doc or README names `tcgreplay.demo.gs`, except where it explains the move.

## Constraints

- The playmat stays hosted on its existing DigitalOcean App Platform app; the move changes its address, not where or how it runs.
- DNS for tcgreplay.app stays at Cloudflare, where the maintainer registered it.
- The old address must not become a second working sign-in origin: the maintainer rejected multi-address sign-in for a handful of players.
- Players keep signing in with Google through the playmat's existing Google OAuth client; the move updates that client, it doesn't replace the sign-in method.

## Acceptance Criteria

- [ ] **Everything answers at the new address**
  `https://tcgreplay.app/` returns the home page, `/docs/` the docs and `/board` the board. Every sign-in and connection address the playmat publishes at tcgreplay.app names only tcgreplay.app.
- [ ] **Board links name the new address**
  Every board link the assistant hands out, when connected through `https://tcgreplay.app/mcp`, starts with `https://tcgreplay.app/`.
- [ ] **Full connect-and-play at the new address**
  A fresh connection to `https://tcgreplay.app/mcp` from each of claude.ai, ChatGPT and Claude Code completes Google sign-in, a simple tool call succeeds, and the board link it hands out opens the board signed in, with no error shown at any point.
- [ ] **Valid HTTPS, plain HTTP redirected**
  `https://tcgreplay.app` presents a certificate that a browser accepts without a warning, and `http://tcgreplay.app/docs/connect/` ends up at `https://tcgreplay.app/docs/connect/`.
- [ ] **No www anywhere**
  The built website, docs and README never name `www.tcgreplay.app`.
- [ ] **Old pages redirect permanently, keeping path and query**
  `https://tcgreplay.demo.gs/docs/connect/` and `https://tcgreplay.demo.gs/board?x=1` each get a permanent redirect to the same path and query on `https://tcgreplay.app`; `http://tcgreplay.demo.gs/docs/` ends up at `https://tcgreplay.app/docs/`.
- [ ] **Old assistant connection shows the moved message**
  claude.ai and ChatGPT, each with a connector still set to `https://tcgreplay.demo.gs/mcp`, show the player a message, in the conversation or the connector's error, that names `https://tcgreplay.app/mcp` as the address to reconnect at. It isn't only a generic failure.
- [ ] **The old address signs no one in**
  Starting a sign-in through `tcgreplay.demo.gs` never completes a sign-in there; the player ends up pointed at tcgreplay.app.
- [ ] **Retiring the old address needs no release**
  With the old domain removed from hosting and DNS and no new build deployed, `https://tcgreplay.app` keeps working for website, board and assistant.
- [ ] **Console steps are written and checkable**
  The maintainer's instructions list the DNS, hosting-domain and Google sign-in changes in order. Each step has a check whose result is visible, such as a command or page and what it should show.
- [ ] **No stray old address**
  A search of the built website and the README for `demo.gs` finds it only in text that explains the move.

## Technical Approach

- Switch the playmat's single public address to tcgreplay.app rather than teaching the server about two addresses; everything that derives from that one address (sign-in issuer, assistant connection, board origin, board links) then follows.
- Answer the old address by forwarding pages and by giving the old assistant connection a deliberate "moved" answer (see Constraints on sign-in). How the moved message reaches the player inside the assistant is open: a plain sign-in failure at the old address would likely push the assistant into a confusing re-sign-in, so the plan should check what claude.ai and ChatGPT actually show and pick the answer that surfaces the message.
- Prefer doing the redirects at the hosting or Cloudflare layer where that keeps the old address removable by configuration alone; fall back to the server only where the platform can't express it.
- Risk: Cloudflare's proxy in front of App Platform can block App Platform issuing its certificate for tcgreplay.app; the console steps should say whether the records are proxied and how to check the certificate was issued.
- Risk: the Google OAuth client needs the new callback address added before the switch, or sign-in breaks at the moment of the move; the console steps should order that first.

## Success Metrics

- The ChatGPT plugin submission (a later spec in the epic) goes in naming tcgreplay.app, with no need to change the address afterwards.
- No player asks the maintainer for help reconnecting in the first two weeks after the move.
- In the first week after the move, the hosting platform's request logs show no server error at tcgreplay.app caused by the address change (sign-in, connection or board origin).

## Non-Goals

- Keeping existing assistant connections or board sign-ins alive across the move: players sign in and connect again at tcgreplay.app.
- Visitor analytics, observability, the privacy and terms pages and the Pokémon disclaimer: separate specs in the public-launch epic.
- The ChatGPT plugin files, domain verification and the Plugin Directory flow in the docs: the ChatGPT-prep and docs specs. Docs change here only where they name the address.
