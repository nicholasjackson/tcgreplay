## Overview

The maintainer can build any card set ahead of time instead of the playmat pulling cards on demand. An import does the mechanical work of gathering and cleaning each card from the upstream sources and lists everything still in doubt. An assistant then checks each doubtful card against its printed image and records corrections, which every later import keeps. The result is kept with the project, where it can be reviewed and changed, so the card data the playmat will use is complete and correct before anyone plays with it.

## Requirements

- [x] **Import a set**
  The maintainer can import a named card set in a single step. The import gathers the set's cards from the upstream card sources, combines them into one definition per print, and stores the result with the project.
- [x] **Update an imported set**
  The maintainer can re-import a set that was imported before. Prints added upstream since the last import, such as promos, illustration rares and secret rares, are added, and text or art changed upstream is updated.
- [x] **Clean up upstream text**
  An imported card's text holds no markup. Fields that one source lacks are filled from another source that has them, including evolves-from, regulation mark and effect text.
- [x] **Import report**
  Every import produces a report listing what still needs attention:
  - fields the sources disagree on;
  - Trainers and special Energy with no effect text;
  - Pokémon with no attacks;
  - evolved Pokémon with no evolves-from;
  - prints with no image;
  - cards whose text changed since the previous import;
  - corrections that the sources now agree with.
- [x] **Corrections survive re-import**
  The maintainer can record a hand correction to any card. Every later import of that set applies it, and no import ever discards or overwrites it.
- [x] **Agent-verified import**
  The maintainer can ask the coding assistant to import a set. The assistant runs the import, checks each reported card against its printed image and the sources, and records corrections. It repeats this until nothing is left in the report without a recorded reason, then summarises the changes for the maintainer to review.
- [x] **Built sets are reviewable**
  Imported sets and their corrections are kept in the project's history as readable text. The maintainer can review, diff and edit them like any other change.
- [x] **Room for other languages**
  A built set keeps a card's language-independent facts apart from its wording, so that wording in another language can be added later without reshaping existing sets.
- [x] **Each print names its image source**
  Every built print records where its image comes from, whenever any source has an image for it.
- [ ] **Every English set built**
  Every English set the upstream sources list is imported and verified into the project, not only new sets, so the full catalogue exists as built data.
- [x] **Documentation for importing**
  The project documentation describes how a set is imported and verified, including how to record a correction.

## Constraints

- **Card data is data, not code.** Built sets hold card definitions as data kept apart from the program, following the user's principle: "Clean separation is data in the bucket, logic and presentation in the binary."
- **Built data lives with the code base.** Imported sets and corrections are kept in the project repository so they can be changed and reviewed ("the built deck should live with the code base so that we can change it").
- **Verification is an agent's job, packaged as a project skill.** Code does what it can mechanically, and a coding-assistant skill does the checking ("we do what we can in code but it needs an agent to verify"; "offline set build needs a skill too").
- **The assistant never commits.** The verification skill leaves its changes uncommitted for the maintainer to review, per the user's standing instruction never to commit unless explicitly asked.
- **Game logic reads English text.** The playmat's reading of card effects works on English wording, so English text must always be present for every card, whatever other languages are added later.

## Acceptance Criteria

- [x] **Import writes a built set**
  Running the import for Delta Reign leaves a built set in the project. It holds one definition for every print the upstream sources list for the set (141 at the time of writing), each with its name, category and set.
- [x] **Re-import adds new prints**
  When a set is re-imported after upstream gains a print, the built set then holds that print, and every print that was already there is still present.
- [x] **Re-import picks up upstream changes**
  After upstream changes a card's text or image, a re-import shows the new value in the built set, unless a recorded correction covers that field, in which case the corrected value stays.
- [x] **No markup in built text**
  No attack, ability or effect text in a built set contains HTML tags. A Delta Reign card whose upstream text carried energy-symbol markup reads as plain words.
- [x] **Missing fields filled from the other source**
  For Delta Reign, every Trainer and special Energy in the built set has effect text, every Stage 1 and Stage 2 Pokémon has an evolves-from, and every card has a regulation mark. Each holds whenever at least one source provides the field.
- [x] **Report lists every kind of gap**
  For a set where a card lacks effect text in every source, the import report names that card. The same holds for each other category in the requirement: a source disagreement, a Pokémon with no attacks, a missing evolves-from, a missing image, text changed since the last import, and a correction the sources now match.
- [x] **Correction survives re-import**
  After a correction is recorded for a card and the set is imported again, the built card still shows the corrected value. The correction record is unchanged.
- [x] **Agent-verified import finishes clean**
  When the maintainer asks the coding assistant to import a set, the session ends with:
  - every item in the final import report either resolved or carrying a recorded reason;
  - a summary of what changed in the built set;
  - nothing committed by the assistant.
- [x] **Built sets are readable text in history**
  Built sets and corrections can be opened in a text editor, and a re-import that changes one card shows as a diff touching only that card's entries.
- [x] **Language-independent facts kept apart**
  A built set's HP, types, attack costs, damage, retreat and stage are stored once, apart from its English wording. Adding a second-language wording for one card leaves the existing English wording and the language-independent facts byte for byte unchanged, and a re-import of the set still succeeds with its English wording unchanged.
- [x] **Image source recorded**
  Every Delta Reign print for which any source has an image names that image source in the built set, and every print with none appears in the import report.
- [x] **Every English set built**
  The project holds a built set for every English set the upstream sources list. Each holds every print either source lists, and each set's final import report has no item without a recorded reason.
- [ ] **English text everywhere**
  Every card in every built set has an English name, and English text for every attack, ability and effect it has.
- [x] **Docs describe importing**
  The documentation describes importing and verifying a set and recording a correction.

## Technical Approach

- **Sources.** TCGdex stays the main source. TCG Live's export on malie.io fills gaps, since on day one it had full English text, the regulation mark and images for Delta Reign. malie.io is a fan project, so prefer using it only at build time, and consider asking on its Discord before relying on it or using its images as a backup for art. Without that agreement the build can still run from TCGdex plus corrections alone.
- **Import is a CLI command on the existing program**, for example `tcgreplay sets import <set>`. It writes built sets and a machine-readable report that the skill consumes, so the skill keeps no list of its own.
- **Corrections in their own file per set**, separate from the built output and re-applied on each import. The corrections file is also where pair play and missing rule text, such as the Legendary Stadium rule, are recorded.
- **Built format.** One file per set in the playmat's own card format, holding a language-independent core plus per-language text. Use readable JSON in the repo and compress it when publishing.
- **Known risk:** TCGdex image URLs for new sets may arrive weeks later, so a re-import picks them up.

## Non-Goals

- **Languages other than English.** No other language is imported, published or shown.
- **Japanese-only sets.** These form a separate catalogue with their own sets and numbering, not a translation of the English sets.
- **Automatic detection of new sets.** No scheduled job imports new sets or new prints on its own. The maintainer starts each import.
- **Publishing or serving the built sets.** Getting built sets to playmats is a separate spec in this epic.
