# Feature: 20261120140830-52277437-studio-redesign

## Overview

TCG Replay's board and website get a new look, Studio: a light interface around a dark mat, a new logo with no Pokémon imagery, and themes each player can choose (light or dark interface; slate, felt or navy mat). The board shows the numbers that decide a turn (HP left, damage, Energy, prizes) at a glance, works well on desktops, tall second monitors, tablets, touch PCs and phones, and keeps every way to rewind and replay a game. Today the board and the website share only a hand-copied set of colours, and every change to the look means editing every part of the board. After this, both draw from one shared set of design values, so they match and future changes to the look are cheap.

## Requirements

- [x] **One shared set of design values**
  The board and the website take every colour, typeface, type size, spacing step, corner radius and shadow from one shared set of design tokens. No design value is defined anywhere else.
- [x] **The Studio board on desktop**
  The board shows:
  - the header;
  - the player blocks: prize pips, pile chips, top of discard;
  - the Bench, with an HP and Energy readout under each card;
  - the Active panel: HP left over maximum, an HP bar, the damage tag and Energy;
  - the turn strip;
  - the hand, with each card's kind;
  - the timeline.

  All of it appears as the Studio design document describes.
- [x] **The Studio board on every other screen**
  - Board areas narrower than 1600px use the desktop mat. Areas 1600px or wider use the landscape mat defined by the wide-screen board design, restyled.
  - A narrow PC with the timeline docked below gets a resize handle, one control row, and a turn list showing each player's half and the prize score after each turn.
  - Tablets and touch PCs get touch-sized controls and a timeline that can be hidden.
  - Phones get the compact layout defined by the touch-friendly board design, restyled, with the timeline as a full-screen sheet.
- [x] **Replay controls in the timeline**
  - Every timeline line has Play from here and Rewind to here.
  - Each turn, and each player's half of a turn, has Rewind and Play for its start.
  - These controls are always visible, never only on hover, and touch-sized on touch devices.
- [x] **Themes**
  Players choose an interface (light or dark) and a mat (slate, felt or navy) from the board's ☰ menu. The default is light with slate. The choice is remembered between visits, and only colours change between themes. The privacy page names these settings among the display settings the board remembers, and lists every outside service the board and the website load from.
- [x] **Studio menus**
  The board's menus use Studio styling in all three containers: a popover where a mouse right-clicks, a panel for touch, and a sheet on a phone.
  - The attack panel gets the damage control with Weakness and Resistance, the target with Change, a one-line Knock Out hint when the damage is at least the target's HP left, and an "Attack X for N" button.
  - The popover for a card in hand gains a Card text item.
  - Target mode, the deck menu, and the Draw N and Look at top N panels are restyled with the same parts.
- [x] **One mark everywhere**
  The card-stack mark replaces the current logo in the board header, on the website, as the favicon and app icons, in the project's docs images, and as the ChatGPT listing icon, which is redrawn from the mark. No Poké Ball imagery remains in any logo or icon.
- [x] **A Studio card back**
  Face-down cards (deck, prizes, the opponent's hand, unknown cards) show a new navy back carrying the mark, in place of the current red and blue back.
- [x] **The Studio website**
  Every page is restyled with a shared header and footer:
  - the home page, with a How it works section;
  - the docs layout: sidebar, breadcrumb, On this page, copy blocks, prompt bubbles, numbered steps, callouts and code blocks;
  - Coaching workflows, grouped into After a game, Practice and Play;
  - What's new, Example game, Limits (with stat tiles), Privacy, Terms and the 404 page.

  The header has Guides, Example, Limits and What's new as links and Get started as a button. Home and Privacy are no longer header links; the logo goes home and Privacy is in the footer.

## Constraints

- **Follow the designs.** The solution must follow the Studio design document (`studio/design.md` in the project's `design` design source). It must keep the behaviour and layouts defined in the touch-friendly board design (`mobile-board/design.md`) and the wide-screen board design (`wide-board/design.md`), in the same source.
- **Token values come from the design system.** They must match the TCG Replay Studio design system (https://claude.ai/artifact/8uqeTrkeXAc2YYTUvwtEjK). Where the design system and the design document disagree, the design document wins and the design system is corrected.
- **One release, tokens first.** The board, the website, the mark and the tokens must ship together in one release. Within the work, every component must be moved onto the tokens with its look unchanged before any part of Studio is applied.
- **Typefaces from Google Fonts.** IBM Plex Sans and Mono load from Google Fonts on the board and the website, and Google Fonts is the only new outside host either may load from. The privacy page must list Google Fonts as an outside service; today it says Cloudflare's visitor-counting script is the only thing the website loads from another site.
- **Same frameworks.** The board must stay a Svelte 5 app, and the website must stay an Astro site.
- **Website content keeps its sources.** Website pages must keep drawing their content from the existing site facts, the shared fan-project notice, the What's new data and the docs content. Hosted limits must come from the site facts and must never be hard-coded into pages.
- **Replay controls stay.** No existing replay control in the timeline may be removed.
- **Themes stay in the browser.** Theme choices must be remembered only in the player's browser, like the board's other display settings.
- **Touch targets.** Every control must be at least 44px under a coarse pointer.
- **Contrast.** Every interface-and-mat combination must meet 4.5:1 contrast for text, and 3:1 for large text, focus rings, markers, and any border that is the only thing showing a control's edge.
- **Existing suites.** The existing browser test suites must keep passing. They may be changed only where a requirement of this spec makes an old expectation untrue (the new navigation, the guide grouping, Google Fonts as the one allowed outside font host, the privacy page's settings and outside services), and each such change is recorded in the plan.
- **The landscape mat lands first.** The wide-screen landscape mat (the wide-screen board design's implementation) must be committed to the main line before this work starts; this work restyles it rather than rebuilding it.
- **The listing icon** must stay a square PNG of at least 512px rendered from an editable SVG source, with no Pokémon trademark.

## Acceptance Criteria

- [x] **The token step changes nothing visible**
  Screenshots of the board (desktop, docked timeline, tablet, phone) and of every website page, taken before and after the components move onto tokens, match.
- [ ] **No values outside the tokens**
  - No board or website component uses a colour or a type size that does not come from the shared tokens, and an automated check fails if one does.
  - Review finds no spacing, radius or shadow value outside the tokens.
- [x] **Contrast holds in every theme**
  An automated check confirms that every text-and-background pairing the tokens define meets 4.5:1. Large text (24px and up), focus rings, markers, and any border that is the only thing showing a control's edge must meet 3:1. This holds for both interface themes and all three mats, and the check passes.
- [x] **Existing suites still pass**
  The board's and the website's existing browser test suites pass. They are changed only where a requirement of this spec made an old expectation untrue, and the plan lists each change.
- [x] **Themes switch and stick**
  - On a first visit with no saved choice, the board shows the light interface with the slate mat.
  - Each of the six interface-and-mat combinations can be chosen from the ☰ menu.
  - Choosing one changes colours only: every element keeps its position and size.
  - The choice survives a reload.
- [ ] **The board matches the design on every screen**
  Screenshots of the board on desktop, at 1600px and wider, on a narrow screen with the timeline docked below, on a touch tablet or touch PC, and on a phone are reviewed against the design and accepted by the maintainer.
- [x] **Replay controls work from every line**
  - From any timeline line, Play from here plays on from that event, and Rewind to here rewinds to just after it.
  - The Rewind and Play buttons for a turn, or for a player's half, act on that turn's or half's start.
  - On touch devices each control is at least 44px.
- [x] **The attack panel works as designed**
  The attack panel shows:
  - the attack's damage with Weakness and Resistance toggles;
  - the target with a Change button;
  - one button naming the result, such as "Attack Kadabra for 130".

  "N is enough to Knock Out X" appears exactly when the chosen damage is at least the target's HP left, and it never stops an attack.
- [x] **Menus open in the right container**
  - A mouse right-click opens the popover.
  - A tap on a tablet or touch PC opens the panel.
  - A tap on a phone opens the sheet.
  - Each matches its Studio design.
  - The hand popover offers Card text.
  - Target mode, the deck menu, and the Draw N and Look at top N panels use the Studio styling.
- [x] **The mark replaces the old logo**
  No shipped logo or icon contains Poké Ball imagery. The redrawn ChatGPT listing icon passes the existing listing icon test. The board, the website, the favicon and the docs show the mark.
- [x] **Face-down cards show the Studio back**
  Every face-down card on the board shows the navy back with the mark.
- [x] **Website pages match the design**
  - Each website page, including the shared header and footer and the home page's How it works section, matches its Studio design.
  - The Limits tiles always show the current hosted limits.
  - Coaching workflows are grouped into After a game, Practice and Play.
  - The header shows the agreed links and the Get started button.
- [x] **The privacy page is up to date**
  The privacy page lists the theme settings among the display settings the board remembers, and lists every outside service the board and the website load from.

## Technical Approach

- **One token source.** Define the tokens once and have both apps consume the same generated CSS custom properties, mirroring the design system's token names. The interface theme switches through a theme attribute; the mat switches by pointing the mat tokens at the chosen mat's set. The website's hand-copied colour file is replaced by the shared tokens.
- **Studio component by component.** After the no-visual-change step, apply Studio one component at a time, replacing the screenshot baselines with Studio ones as each lands.
- **Enforce the tokens with tests.** The stray-value check and the contrast check run with the existing test suites, so a regression fails the build.
- **Typefaces.** Load IBM Plex from Google Fonts, with system font fallbacks.
- **One logo source.** The mark's SVG is the source of truth for every icon, rendered to PNG where needed. The listing icon follows its own constraint.

## Success Metrics

- Changing one token value restyles the board and the website together, with no component edits.
- The stray-value and contrast checks stay green on every later change, so hard-coded values do not creep back.

## Non-Goals

- A dark theme for the website.
- Changing the game's actions, gestures, dragging, target mode or menu model. The only new controls are those listed in the requirements (the docked timeline's handle and turn list, hiding the timeline, the phone's timeline sheet, theme switching, Card text and the Knock Out hint).
- How card images are drawn: the board keeps showing the real card images.
- Changing what the website says, beyond the new navigation, the guide grouping and the How it works section.
- Syncing the board's components to Claude Design (Anthropic's design tool), which needs React components.
- Offering the alternative visual directions considered during design (Night Table, Tournament Felt) as choices.
