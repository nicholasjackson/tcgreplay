## Overview

Give every signed-in Google account its own game on the hosted playmat, so several people can share one server without seeing or changing each other's boards. All of an account's claude.ai conversations and board tabs share that account's one game, and board links only open for their owner. Games left idle are cleared so the server can keep serving everyone, and the desktop is unaffected.

## Requirements

- [ ] **Games are isolated**
  One account's imports, moves and rewinds never affect another account's game.
- [ ] **Shared across an account's conversations, tabs and devices**
  All of an account's claude.ai conversations and board tabs, on any device, see and act on the same game, and importing in one replaces it for all.
- [ ] **Actions stay with their user**
  Every action Claude takes in a user's conversation affects only that user's game.
- [ ] **Owner-only board**
  A board link opens only for the account whose game it is. Any other signed-in account sees a "not your game" message and nothing of the game.
- [ ] **Signed-out visitors see nothing**
  A visitor who is not signed in and opens a board link is asked to sign in first and sees nothing of the game.
- [ ] **Board shows only its owner's game**
  A board shows changes to its owner's game as they happen, and only those.
- [ ] **Own name on the board**
  The board labels the signed-in user's side with their own name.
- [ ] **Idle games dropped**
  A game with no activity for longer than a time the operator sets is dropped. Activity is any action through Claude, any move on the board, or opening the board; a board tab simply left open does not count. The account's next action says the game expired and asks for the saved game record to be imported again.
- [ ] **Expired games free their place**
  Once an idle game expires it no longer counts against the signed-in user limit, so a new user can start one.
- [ ] **Desktop unaffected**
  The desktop (the playmat launched locally by Claude Desktop or Claude Code) keeps a single game with no accounts.

## Constraints

- Must use the signed-in Google account as the identity that decides whose game a request touches.
- Must keep one game per account.
- Must keep every account's game in memory only, like the rest of the playmat.
- The hosted server must run as a single instance, because accounts' games are not shared across copies.
- Must build on the Google sign-in and limits from the google-login spec, with no second sign-in or limit mechanism.

## Acceptance Criteria

- [ ] **Isolation**
  Accounts A and B each import a different game. Each sees only their own game through Claude and on the board, and a move by A leaves B's game unchanged.
- [ ] **Same account, two conversations**
  A move made from one of an account's conversations is reflected in what its other conversation sees when it next reads the board, and on that account's open board tab.
- [ ] **Import replaces for the account**
  An import in one conversation replaces the game every one of that account's conversations and tabs sees.
- [ ] **Owner-only link**
  Account B opening A's board link sees "not your game" and no cards.
- [ ] **Signed-out link**
  A visitor who is not signed in opening a board link is asked to sign in and sees no cards.
- [ ] **Live updates scoped**
  A's open board shows A's moves as they happen and receives no updates when B acts on B's game.
- [ ] **Idle drop**
  With the idle time set to 2 minutes, after 2 minutes with no activity the next action through Claude or board load reports that the game expired and asks for it to be imported again.
- [ ] **Open tab does not keep a game**
  With the idle time set to 2 minutes and a board tab left open with no activity, the game still expires.
- [ ] **Activity keeps a game**
  With the idle time set to 2 minutes, a game acted on every minute for 5 minutes is still available, with its moves intact.
- [ ] **Expired game frees a place**
  With the server at its signed-in user limit, once one account's game expires, a new account can sign in and start a game.
- [ ] **Own name**
  Each account's board shows their own name on their side.
- [ ] **Desktop**
  The desktop still has one game and no sign-in.

## Technical Approach

- Prefer replacing the single shared "current game" with a lookup by signed-in account, used by both the connector and the board's live connection.
- Risk: today's server and board assume one game shared by every connection; this is likely the largest change in the epic.
- Risk: memory grows with the number of accounts; the idle drop and google-login's per-account request cap and signed-in user cap are what bound it.
