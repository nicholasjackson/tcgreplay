# Card images from the playmat's own CDN

The hosted playmat can now serve card images from its own DigitalOcean Spaces CDN. When the shared card store is configured, each card image the board shows is copied once from TCGdex into the bucket, and the board loads it from the bucket's CDN from the next page load on. Images without a copy still show at once from TCGdex, and if the CDN cannot be reached the board falls back to TCGdex. The desktop app, and hosted mode without the shared store, load images from TCGdex exactly as before.

> Derived from project tcgreplay, spec/plan 20261104090640-25f673ed-card-image-cdn. See the project-level record for the full feature.

## What changed in this repo

- `internal/webui`: the optional `Images` source on the board server, and the `image_fallback` field on `/api/card`.
- `web/src`: the card, zoom and preview images try `image`, then `image_fallback`, then the stand-in (`imageSrc` and `nextImageStage` in `store.svelte.js`). There is a new Playwright spec, `web/e2e/images.spec.js`.
- `internal/spaces`: `Client.List` (ListObjectsV2) and `Config.PublicBase()`. The `spacestest` stand-in gained listing with paging, unsigned reads of public objects, `Public(key)` and `PageSize(n)`.
- `internal/cards`:
  - The new `ImageCache` (`images.go`): the copier, the start-up listing, never writing over an object, the image breaker and the hourly count line.
  - The tiered store's breaker, factored into `breaker.go`.
- `cmd/tcgreplay`: `hostedCardDB` builds and logs the image cache when the shared store is on, `runHosted` runs it, and `hostedBoard` hands it to each account's board.
- `.do/app.yaml`, `Dockerfile` and `TCG Review Playmat Design and Build Plan.md`: operator documentation, including the new step to enable the bucket's CDN.

## Why

The board loaded every card image from TCGdex. Serving copies from the playmat's own CDN gives hosted players art from the playmat's own address, asks TCGdex for each image only once, and keeps art loading when TCGdex is slow. The fallback means no player loses an image while copies are being made or if the CDN fails.

## Still to do (operator)

Enable the CDN on the Spaces bucket, check that the access key can list the bucket and write public-read objects, and redeploy. Until then the board's CDN addresses fail and fall back to TCGdex. The manual checks are in the implementation test plan.
