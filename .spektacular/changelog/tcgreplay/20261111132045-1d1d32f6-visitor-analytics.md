# Cookieless visitor counting for tcgreplay.app

The hosted playmat can now count visits to the public website and to the board with Cloudflare Web Analytics. It uses no cookies, stores nothing in the browser and shows no consent banner. Counting is off until the maintainer sets a Cloudflare site token, and the playmat also refuses to count until its own privacy page describes counting. Local runs, the desktop app and the test suites never count. A board session counts once, however much the player moves around the board.

> Derived from project tcgreplay, spec/plan 20261111132045-1d1d32f6-visitor-analytics. See the project-level record for the full feature.

## What changed in this repo

- **`internal/webanalytics` (new).** Holds Cloudflare's manual beacon tag (`"spa":false`), the token check, the on/off decision with a start-up status line, and the wrapper that adds the tag to successful `GET` HTML pages for the public host only.
- **`internal/site`.** `DescribesVisitorCounting` reports whether the embedded privacy page carries `data-retention="visits"`.
- **`cmd/tcgreplay`.** Adds the new setting `TCGREPLAY_WEB_ANALYTICS_TOKEN` (`-web-analytics-token`). The start-up log says `visitor analytics: on for <host>`, or off with the reason, never the token. Only the website and the `/board` page route are counted. Hosted route tests cover:
  - one beacon on public-host pages and the signed-in board;
  - none on other hosts, redirects, sign-in, admin, MCP or assets;
  - pages byte-identical to before when counting is off;
  - no token in the log.
- **Operations.**
  - `.do/app.yaml` declares the setting without a value.
  - The Dockerfile's settings notes and the design doc explain it: set it only once the privacy page describing counting is live, and clear it to stop counting (a restart is enough).
  - `make docker-run` deliberately does not pass it.
- **Test servers and browser suites.** The website and board test servers take `-analytics-token`. `site/e2e/analytics.spec.js` and `web/e2e/analytics.spec.js` check the real built pages with Cloudflare stubbed or blocked:
  - one beacon per page;
  - no other host;
  - no cookies or extra storage;
  - no second beacon on the board;
  - everything works with the beacon blocked.
- **Still to do by hand.** Switching counting on for tcgreplay.app is the maintainer's step after deploy: create the Cloudflare site with the manual snippet, then set the token. The steps are in the implementation test plan.

## Why

The maintainer needs to know whether the launched site is used: visits, top pages, referrers, countries and devices, plus board sessions. Counting must not identify anyone or need a consent banner. This repo serves both the website and the board, so it is the one place the beacon can be added once for both.
