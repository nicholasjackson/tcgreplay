# Google sign-in for the hosted playmat

The hosted playmat now asks for a Google account. Adding it as a custom connector in claude.ai, or opening a board link, goes through Google sign-in once, and the sign-in lasts until the server restarts. The board shows who is signed in and has a Sign out button. Operators can cap requests per account and the number of signed-in accounts. Claude Code and Claude Desktop, which run the playmat locally, are unchanged and never ask for sign-in.

> Derived from project tcgreplay, spec/plan 20261017123240-21493a95-google-login. See the project-level record for the full feature.

## What changed in this repo

- **New `internal/hostauth` package:**
  - an OAuth authorization server for MCP clients (protected-resource and server metadata, `/register`, `/authorize`, `/token` with PKCE and refresh rotation) that delegates login to Google;
  - board sessions (`/auth/login`, `/auth/session`, `/auth/logout`, `/auth/signed-out`);
  - the per-account request limit and the signed-in user cap;
  - `/healthz`;
  - a test helper package (`hostauthtest`) with a fake Google and helpers that sign test clients in through the real routes.
- **`tcgreplay -hosted`:**
  - new settings: `TCGREPLAY_GOOGLE_CLIENT_ID` / `-google-client-id`, `TCGREPLAY_GOOGLE_CLIENT_SECRET`, `TCGREPLAY_RATE_LIMIT` / `-rate-limit` (default 300) and `TCGREPLAY_MAX_USERS` / `-max-users` (default 10);
  - refuses to start without the credentials;
  - puts `/mcp` behind the token check and the board behind the session check, with the request limit on MCP requests and board actions.
- **Board server (`internal/webui`):** an optional `Limit` hook, called before each board action. It is unset on the desktop.
- **Board client (`web/`):** shows the signed-in account and a Sign out button on the hosted board. It sends the user through sign-in again when the session has ended.
- **Deployment:**
  - `.do/app.yaml` uses `/healthz` for the health check and declares the Google credentials as secrets, plus the limits;
  - the Dockerfile notes and `make docker-run` pass the new settings;
  - `go.mod` makes `golang.org/x/oauth2` a direct dependency.
- **Docs:** the design document has a "Hosted sign-in" section covering the settings and the one-time Google and App Platform setup.

## Why

The hosted trial was open to anyone with its address. Requiring Google sign-in keeps out anonymous traffic and abuse, and the limits stop one account from overloading the server. Every request now carries a signed-in account, which per-user games will build on.

## Upgrading

- **Before deploying:** set `TCGREPLAY_GOOGLE_CLIENT_ID` and `TCGREPLAY_GOOGLE_CLIENT_SECRET`. Without them the hosted app will not start.
- **After deploying:** switch the platform health check to `/healthz`.
- **claude.ai:** remove any connector added before sign-in existed and add it again at `https://<domain>/mcp`.
