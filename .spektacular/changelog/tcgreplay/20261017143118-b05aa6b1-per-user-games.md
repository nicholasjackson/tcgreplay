# Per-account games on the hosted playmat

The hosted playmat now gives every signed-in Google account its own game. Each person's Claude conversations, board tabs and devices share their one game, and nobody else can see or change it. Board links open only for their owner, and a game left idle is cleared, with a message asking for its saved record to be imported again. Clearing it frees its place for another user. The desktop playmat is unchanged.

## What changed in this repo

- **New `internal/usergames` package** (hosted only). The registry gives each Google account its own game manager and board server, with a stable, opaque board handle. It records activity, expires idle games with a notice, sweeps in the background, and forgets placeless accounts after a day. It owns the user cap's places (it implements `hostauth.Places`). It also serves the board's front door: own board only, a "Not your game" page for another account's link, and activity counted on page loads and board moves but not on open connections.
- **`internal/mcpserver`**: an optional `Resolve` hook binds each tool call to the caller's game and board link through the single tool-registration helper. When it is unset (the desktop), results, the tool list and the instructions are unchanged.
- **`internal/game`**: `Manager.Expire`, `Notice`, `OnClear` and `ErrExpired`. After expiry, every request that needs the game gets the notice until a new game or import replaces it.
- **`internal/webui`**: the state message carries `notice` when there is no game, and open boards refresh when the game is cleared. The hub now keeps only the current game, so replaced games are freed.
- **`internal/hostauth`**: `Config.MaxUsers` was replaced by `Config.Places`. Sign-in asks `Places.Admit`, and the store calls `Places.Release` when an account's last live sign-in ends. `BusyError` keeps the busy wording in one place, and `WithAccount` is exported.
- **`cmd/tcgreplay`**: hosted mode builds the registry and wires it in as the resolver, the board front door and the places provider. There is a new `-idle-timeout` / `TCGREPLAY_IDLE_TIMEOUT` setting (default 60m, `0` never, invalid stops start-up). The idle sweep runs for the life of the server, and the start-up log shows the setting. `-max-users` now counts places.
- **`web/`**: the board shows the expiry notice on its landing, and labels the player's side with the signed-in account's name when the game names none.
- **Docs and deployment**: the design document describes per-account games, board links, the idle drop, places and the single-instance requirement. `.do/app.yaml` declares `TCGREPLAY_IDLE_TIMEOUT: "60m"` and notes that `instance_count` must stay 1.
- **Tests**: unit tests for the registry, board front door, places, expiry and per-call resolution. End-to-end hosted tests use two signed-in accounts and an injected clock to cover isolation, shared sessions, owner-only links, scoped live updates, idle drop, open tabs, places and the settings.

## Why

The hosted trial served one shared game to everyone who signed in. To let several people use the server at once, the single current game became a lookup by signed-in account for both the connector and the board. The idle drop and places keep memory bounded on the single instance.
