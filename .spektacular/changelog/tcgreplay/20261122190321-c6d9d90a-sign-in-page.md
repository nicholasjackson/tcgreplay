# TCG Replay sign-in page and reviewer password accounts

Connecting an assistant to the hosted TCG Replay playmat, or opening the board in a browser that is not signed in, now shows TCG Replay's own sign-in page. Players choose "Sign in with Google" there and keep the same account and games as before. The operator can also set up username and password accounts for directory reviewers and invited users, which sign in on the same page, always get a place when the playmat is full, and never become admins.

> Derived from project tcgreplay (local), spec/plan 20261122190321-c6d9d90a-sign-in-page. See the project-level record for the full feature.

## What changed in this repo

- **Sign-in flow** (`internal/hostauth`): both entry points record the sign-in and redirect to `/auth/signin`; Google starts from the page's button (`/auth/google`), the username and password form posts to `/auth/password`, and every provider ends in one shared completion. Server-rendered pages share a Studio-styled layout with frame refusal, `no-store` and a strict content security policy.
- **Password accounts**: `TCGREPLAY_PASSWORD_ACCOUNTS` (bcrypt `username:hash` entries, one cost for all) is parsed at start-up; sign-ins seal the provider and a hash fingerprint into cookies and tokens, so removed or re-passworded accounts are refused after a restart; failures are throttled per username and per client; nothing about an attempt is logged.
- **Places and identity** (`internal/usergames`, telemetry): password accounts get the reserved place at the player cap and their own player IDs; `TCGREPLAY_REVIEWER` is retired with a start-up warning; the app spec declares the new secret.
- **Board**: the account menu shows a password account's username with "Signed in with a reviewer account".
- **Website**: sign-in and connecting guides, What's new, and the privacy page.
- **Plugin review materials**: test cases, demo script and submission checklist use the reviewer account; a test keeps them from drifting back to Google instructions.
- **Dependency**: `golang.org/x/crypto` (bcrypt).

## Why

OpenAI's plugin review needs a username and password for a demo account that works without codes or approvals, which a Google-only sign-in could not guarantee. This repo is the hosted playmat that reviewers sign in to, so the sign-in page, the accounts and the reviewer materials all live here.
