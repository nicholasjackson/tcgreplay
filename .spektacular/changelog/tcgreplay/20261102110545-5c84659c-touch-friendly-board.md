# Touch-friendly board

The board now works by touch on an iPad and an iPhone. Cards drag with a finger, and a tap opens a card's actions, grouped and sized for the screen. Anything that needs a destination is finished by tapping the board, and attacks, damage and counts are set on screen instead of in browser dialogs. On a phone held upright the board switches to a compact layout that fits the screen width. Mouse use on the desktop keeps working as before.

> Derived from project tcgreplay, spec/plan 20261102110545-5c84659c-touch-friendly-board. See the project-level record for the full feature.

## What changed in this repo

- **Dragging.** `web/src/lib/pointer.svelte.js` is a new Pointer Events drag controller, exposed as the Svelte attachments `draggable` and `dropZone`. It replaces the HTML5 drag helpers in `web/src/lib/actions.js` and every component's drag and drop handlers (`Card`, `Stack`, `Hand`, `Side`, `Strip`). The existing `dropOnStack` and `dropOnZone` still decide what each drop does.
- **Actions.**
  - The menu builders in `web/src/lib/actions.js` return grouped sections.
  - `web/src/components/ActionSheet.svelte` replaces `ContextMenu.svelte`, using `Stepper.svelte`, `AttackPanel.svelte` and `CountPanel.svelte`.
  - `web/src/lib/target.js` and `TargetBanner.svelte` add target mode.
  - The store gains the sheet, target and layout state.
- **Touch styling.** Hover effects are gated by `(hover: hover)`, every touch target is at least 44px under `(pointer: coarse)`, and cards set the callout and selection rules. On touch, the timeline's buttons show without a hover.
- **The phone layout.**
  - `CounterBar.svelte` is new.
  - `Side`, `Hand` and `Strip` gain phone branches, and `Modal` gains a prize view.
  - In `App.svelte`: the reduced header with its controls in ☰, the full-screen timeline, and the turn-upright notice.
- **Tests.**
  - `internal/cards/cardstest` holds the one shared fake card pool for the Go tests.
  - `internal/webui/webtest` builds the fixed test position, and `internal/webui/webtest/cmd/boardtest` serves it (test support only, never in the shipped binary).
  - Playwright 1.64.1 (`web/playwright.config.js`, `web/e2e/`, `web/scripts/check-browsers.js`) runs from `make test` after the Go checks.
- **Notes for developers:**
  - Developers need Chromium for Playwright once: `cd web && npx playwright install chromium`. `make test` says so when it is missing.
  - The touch profiles use Chromium's touch emulation, because Playwright's WebKit doesn't run on every development machine.

## Why

The board was mouse-only: HTML5 drag and drop, right-click menus, hover previews and `window.prompt`. Touch didn't drive any of these on iOS, and the board overflowed a phone. This repo holds the board, so it got the input, menu, layout and test changes. The board server and the game model needed none.
