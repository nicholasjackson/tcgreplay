# Hosted playmat mode

The playmat can now run on the web as a single Docker container. Claude in claude.ai, on the web or a phone, can connect to it as a custom connector and use every playmat tool. Each game it imports, creates, loads or rebuilds comes with a link to a live board that follows Claude's moves and takes the player's own. Pushing to `main` deploys it to DigitalOcean App Platform. The desktop setup with Claude Code and Claude Desktop is unchanged.

> Derived from project tcgreplay, spec/plan 20261017105035-e3f64c1b-web-mcp-docker. See the project-level record for the full feature.

## What changed in this repo

- **`tcgreplay -hosted`** (`cmd/tcgreplay/hosted.go`, `main.go`, `daemon.go`):
  - One plain-HTTP listener serves MCP over Streamable HTTP at `/mcp` and the board on every other path.
  - `-listen` defaults to `:$PORT`, else `:8080`. `-public-url` defaults to `$TCGREPLAY_PUBLIC_URL`, is validated, and falls back to `http://localhost:<port>` with a warning.
  - Logs go to stderr, and the server shuts down gracefully on SIGTERM.
  - `newServer` now takes a board URL; the desktop modes pass `""`. `newHosted` wires the one public URL into both the MCP server and the board.
- **Board links** (`internal/mcpserver/server.go`):
  - `Server.BoardURL` adds `"board"` to the results of `import_log`, `new_game`, `load_game` and `set_opponent_deck`, plus a hosted-only instruction line.
  - Without it, results, tool descriptions and instructions are unchanged.
- **Board** (`internal/webui/server.go`, `hub.go`):
  - `Server.Public` skips the loopback Host guard and allows the public host's websocket origin. With it nil, the loopback guards stay as before.
  - Boards are pinged every 30 s (`pingInterval`) and dropped after 10 s with no answer (`pingTimeout`).
- **Container and deployment**:
  - `Dockerfile` (Node build, then a static Go build, then a distroless non-root runtime) and `.dockerignore`.
  - `make docker-build` and `make docker-run`.
  - `.do/app.yaml`: one App Platform service in `lon`, built from the Dockerfile and deployed on push to `main` only, one instance on port 8080 with a health check on `/` and `TCGREPLAY_PUBLIC_URL=${APP_URL}`. It has a placeholder domain to replace.
- **Tests**:
  - MCP tool tests run over both in-memory and Streamable HTTP.
  - New hosted-mode tests: settings, shutdown, parity, links, the 2 s board-follow check, board moves reaching Claude, and origins.
  - Board tests: public address, and pings.
- **Docs**: a "Hosted mode (trial)" paragraph in `TCG Review Playmat Design and Build Plan.md`, and the package comment of `cmd/tcgreplay`.

## Why

This proves claude.ai can drive a hosted playmat before sign-in and per-user games are added. The hosted mode is a mode of this binary, not a separate program, so the desktop modes keep working unchanged.

**Trial limits:** no login, one shared game for everyone, and games are lost on every deploy or restart.

**After merging:** the owner creates the App Platform app once and points the domain at it through Cloudflare. The steps are in the `.do/app.yaml` header and the design document.
