# Project website for tcgreplay

## What was built

A public website for tcgreplay, served by the hosted playmat itself at https://tcgreplay.demo.gs. It replaces the developer-facing README as the explanation of the tool.

- **Home page (`/`)**:
  - a one-sentence pitch and a "Get started" button;
  - a looping animation of the playmat drawn in the board's own colours and no-art card style. A battle log arrives, the board fills, the coach suggests a play, the game rewinds and a different line is played. With reduced motion it is a still, and it never uses card artwork or Pokémon logos;
  - below the fold, what the tool does and the playmat's connector address with a copy button.
- **How-to pages (`/docs/…`)**:
  - connecting from claude.ai, ChatGPT and Claude Code, each ending with how to check it works;
  - running it on the desktop with the Claude desktop app;
  - signing in and opening the board link;
  - importing a TCG Live game, including what a complete import looks like and what to do about missing lines;
  - one page for each of the seven coaching workflows, each with copyable example prompts;
  - rewinding and trying another line;
  - a ready-made example game: a real game with the opponent's name replaced by "Rival", plus its decklist, both copyable;
  - the hosted service's limits;
  - a short pointer for developers.
- **Privacy page (`/privacy`)**: what the hosted playmat collects at sign-in, keeps while you play, for how long, which outside services are involved, and what it never collects.
- **Every page** carries the unofficial fan project notice naming Nintendo, The Pokémon Company, Creatures and Game Freak, and the TCGdex credit. Pages work at phone width, set no cookies and load nothing from other hosts.

**How it ships.** The site is a static Astro project in `site/`. It is built into a new Go package, `internal/site`, and embedded in the playmat binary the same way the board UI is. A checked-in placeholder keeps Go builds and tests working without Node. The Dockerfile gains a `site` stage, so every merge to `main` publishes the site through the existing App Platform deploy.

**The board moved to `/board`.** The hosted router is now an explicit path table:
- the board page is at `/board`, behind sign-in, rewritten to `/` for the board's own server;
- the board's files, live connection and card lookups stay at the root behind sign-in;
- every other path is the public site.

Board links in tool results are now `https://tcgreplay.demo.gs/board?board=<handle>`. Sign-in returns to `/board`, and the signed-out, sign-in-problem, "not your game", "not an admin" and admin pages link there. `/mcp`, sign-in, OAuth, health and admin routes, and desktop mode, are unchanged.

**The site can't drift from the playmat.** At build time it reads the playmat's own sources and stops on any gap:
- every coaching guide in `internal/guides` must have exactly one workflow page, in the guides' own order and showing each guide's description;
- the requests-per-minute, users-at-once and idle-time limits come from `.do/app.yaml`;
- the example decklist comes from the test corpus.

A Go test (`TestSiteExampleGame`) keeps the example battle log equal to its corpus game with only the opponent's name changed, and proves it imports cleanly with the same result.

**Tests.**
- Go tests cover the site package (resolution, 404, caching, no cookies, content types) and the full hosted route table.
- A Playwright suite (Chromium; 1366×768 laptop and 375 px phone) runs against the built site through the Go handler from `make site-test`, which `make test` now runs. It covers the notice on every page, no sideways scrolling, no cookies or third-party requests, copy buttons, the above-the-fold home page, workflow coverage, the limits, the example game, the animation's beats with the playmat blocked, reduced motion and the 1.5 MB home page budget.

## Why it matters

Until now the only explanation of tcgreplay was a README written for developers, which made the tool hard to share. A Pokémon TCG Live player can now open one link, see the playmat in action, connect it to the assistant they already use (Claude or ChatGPT) and start reviewing their games within minutes. The site also gives Google's OAuth consent screen the home page and privacy policy it needs for an app offered to the public, on the domain the consent screen already trusts.

## Deviations from the plan

- **Site package:** the build output is ignored through a package-level `internal/site/.gitignore`, mirroring the board. Content types come from an explicit table, because the distroless image has no MIME tables. The first acceptance criterion was reworded, with the user's approval, to make clear that mounting the handler belonged to the router task.
- **Router:** two places the plan didn't list also spelled the board as `/` and now say `/board`: the sign-in-problem page's link and the hosted MCP server's fallback board URL. `/board/` is matched exactly. Four existing hosted tests had been hitting `/` for the board and passing only because the site placeholder shares the board's `<title>`; they now use `/board`.
- **Build tooling:** Astro 7.4.7 needs Node 22.23.4 or newer, so the Dockerfile's site stage pins `node:22.23.4`. Telemetry is turned off with an environment variable, and syntax highlighting is off.
- **Home page:** it also keeps the connector address with a copy button, below the fold. Two privacy claims were corrected against the code before publishing; account details live with sign-ins for up to 30 days.
- **Docs plumbing:**
  - copy buttons on Markdown code blocks come from the shared script;
  - the MCP address on the connect page is rendered from the build-time facts;
  - the workflow pairing logic sits in its own module so it can be unit-tested;
  - the limits page is an `.astro` page so it can read the limits.
- **Example game:** before writing its pages, both logs were imported and came out identical apart from the name, which answered the plan's open question. The importer is untouched.
- **Animation:** the coach bubble uses the board's dark note colour directly, because the light-scheme token is pale on the dark felt. The better line's log entry takes no room until it appears.
- **Crawl:** once every nav target existed, the site suite started requiring a 200 for every linked page.
- **Not done in this run:** the human task of entering the home page and privacy addresses on Google's OAuth consent screen. It needs the Google Cloud console and the deployed site, so the user chose to skip it in this run. It is the operator step in the design notes and item O1 of the test plan, to do after the merge deploys.
