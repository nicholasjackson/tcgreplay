# Launch docs: current ChatGPT steps, refresh steps, What's new and a docs index

## What was built

All of this work is on the website (`site/`) in the `tcgreplay` repo. There are no Go changes: the site handler already served `docs/index.html` for `/docs` and `/docs/`.

- **Docs index and shared docs list.** A new helper, `site/src/lib/docs-pages.ts`, holds the docs sidebar's list of pages, each with its link, title, one-line description and order. The sidebar (`site/src/layouts/Docs.astro`) and a new docs index page (`site/src/pages/docs/index.astro`) both render it, so `/docs` and `/docs/` now list every docs page with its description instead of showing "Page not found". The sidebar starts with an "All docs" link to the index.
- **Connecting page rewritten as an Astro page.** `site/src/content/docs/connect.md` was replaced by `site/src/pages/docs/connect.astro`, at the same address with the same title.
  - Kept: the address block, the claude.ai, Claude Code and desktop-app steps, the check prompts, and the domain-move note (which gained `id="moved"`). Every address is printed from `site.mcpURL`.
  - ChatGPT section: it now names the plans that allow a custom connection (Business, Enterprise or Edu on the web; on Business an admin or owner adds it) and follows OpenAI's current flow: Plugins, **+**, **Add custom MCP server**, Server URL, OAuth, accept the warning, **Create as a plugin**, Install, then `@` in a new chat.
  - Plugin Directory steps: they are written into the page behind a new flag, `chatgptDirectory.listed` in `site/src/lib/listing.ts`, which is off. The browser suite fails if any built page mentions the Plugin Directory while the flag is off.
- **One refresh section.** "Refresh after an update" (`/docs/connect#refresh`) gives steps for each assistant:
  - claude.ai: remove the connector and add it again.
  - ChatGPT: Plugins, then **Refresh**.
  - Claude Code: `/mcp`, then **Reconnect**, or restart.

  Each assistant's troubleshooting line links to it, and the sidebar and docs index have a "Refreshing the connection" entry.
- **What's new.** Release notes are kept as checked data in `site/src/data/whats-new.yaml`, newest first, with a `date`, `title`, `refresh` flag and `changes` for each entry.
  - The loader, `site/src/lib/whats-new.ts`, follows the site-facts pattern. It stops the build with an error naming the entry and field when a date, title, refresh flag or change list is missing or malformed.
  - `/docs/whats-new` shows each entry's date, title and changes, and says "Refresh needed" (linking the refresh steps) or "No refresh needed".
  - The first entry, "TCG Replay is public" (2026-11-19), covers:
    - the new address, linking the move note without naming the old host;
    - the ChatGPT steps;
    - What's new, the refresh steps and the docs index;
    - clearer tool names and the new account tool;
    - the terms and privacy pages with footer links;
    - the board's About panel.
- **Tests.**
  - New `site/e2e/docs-index.spec.js` and `site/e2e/whats-new.spec.js`. The second includes Node tests of the loader on fixtures, one per malformed field.
  - `site/e2e/connect.spec.js` gained checks for the plans and "Create as a plugin", the refresh section and its links, and a directory test that follows the flag.
  - `site/e2e/site.spec.js`'s whole-site scan gained the Plugin Directory rule.
  - The suite passes: 264 passed, 2 skipped.
- **Knowledge.**
  - New convention `conventions/whats-new-entries.md`: every player-visible change ships with an entry, and the entry says when it needs a refresh.
  - New gotcha `gotchas/astro-inline-whitespace.md`.

## Why it matters

The public launch moved the playmat to its own address and brought ChatGPT users a new way to connect. Without current docs, ChatGPT users would follow out-of-date steps, and any player whose assistant kept an old tool list after an update would be confused. The docs now give ChatGPT steps that match ChatGPT's settings at launch, one place to learn how to refresh a connection, a What's new page that says when a refresh is needed, and a docs index at the docs' own address. Switching on the Plugin Directory route after OpenAI approves the listing is now a one-line change.

## Deviations from the plan

- The refresh section's link to What's new was added in the What's new task instead of the connecting-page task, because the site crawl fails on a link to a page that does not exist yet.
- The ChatGPT plan list is a `chatgptPlans` constant in `listing.ts`, which the page and the test both read.
- The launch-entry tests read the oldest entry rather than the first, so they stay valid once later entries are added above it.
- Hand-written pages were reflowed so no inline tag starts a new source line, because Astro drops the space before it.
- **Skipped, deferred to the maintainer**: the human task "Switch on the Plugin Directory route" waits on OpenAI approving the listing. Its three acceptance criteria are unticked: the directory steps first, the refresh-section note, and a What's new entry announcing the listing. The steps are in the test plan.
- The launch entry is dated the day it was built (2026-11-19). The maintainer corrects it in the wording review if launch day differs.
