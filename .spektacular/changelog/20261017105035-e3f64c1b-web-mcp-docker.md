# Hosted playmat: MCP over HTTP, board links, Docker and App Platform

## What was built

The `tcgreplay` binary has a fourth run mode, `tcgreplay -hosted`. Beside the stdio shim, `-daemon` and `-no-daemon`, it serves the whole playmat from one plain-HTTP port so it can run as a container behind an HTTPS proxy:

- **One address.** MCP is served at `/mcp` over the official Go SDK's Streamable HTTP transport, with stateful sessions, a 4 h idle timeout and the SDK's localhost protection turned off. The board's existing routes (`/`, `/ws`, `/api/card`) serve every other path. All MCP sessions share one game manager and one MCP server, as the daemon does.
- **Settings, not code.**
  - `-listen` defaults to `:$PORT`, else `:8080`.
  - `-public-url` defaults to `$TCGREPLAY_PUBLIC_URL`. It must be http or https, with a host and no path, query, fragment or user info. Without it, hosted mode falls back to `http://localhost:<port>` and logs a warning.
  - Hosted mode logs only to stderr. On SIGTERM it shuts down gracefully, letting in-flight requests finish.
- **Board links.** When the MCP server has a board URL, which only hosted mode sets, the results of `import_log`, `new_game`, `load_game` and `set_opponent_deck` carry `"board": "<public-url>/"`. The server instructions also gain one line asking the assistant to give that link to the player. The public URL is the only source for the links: the request's `Host` is never trusted.
- **The board in hosted mode.** The board server accepts an optional public URL. With one, it skips the loopback `Host` check and accepts websocket connections from the public host, while other sites are still refused. Without one, the desktop default, both loopback guards stay exactly as before. Every open board is pinged every 30 s and dropped if it doesn't answer within 10 s, which keeps it alive under Cloudflare's ~100 s idle limit. The existing client already reconnects and reloads.
- **Packaging.**
  - A three-stage `Dockerfile`: Node 22 builds the Vite board UI, Go 1.27 builds a static binary with the UI embedded, and the binary runs as `tcgreplay -hosted` on `gcr.io/distroless/static-debian12:nonroot`. That image provides CA certificates for TCGdex, and games and the card cache are written under `/home/nonroot`.
  - A `.dockerignore`.
  - `make docker-build` and `make docker-run` targets (`IMAGE` and `PUBLIC_URL` can be overridden).
- **Deployment as code.** `.do/app.yaml` defines one DigitalOcean App Platform service in `lon`:
  - built from the Dockerfile and deployed on every push to `main` only;
  - one `apps-s-1vcpu-0.5gb` instance, `http_port: 8080`, health check on `/`;
  - `TCGREPLAY_PUBLIC_URL=${APP_URL}`, an ingress rule for `/`;
  - a placeholder primary domain for the owner to replace.
- **Tests.**
  - Every existing MCP tool test now runs over both the in-memory and the Streamable HTTP transport.
  - New hosted tests cover settings resolution and validation, a clean shutdown (including the real `main()` in a child process), tool-list and schema parity over HTTP, and links that follow the configured address.
  - They also check that a Claude `move` reaches an open board within 2 s (about 1 ms in-process), that a board move is visible to Claude, and that the public origin is accepted while foreign origins are refused.
  - Board tests cover the public address, and pings using a raw websocket client.
- **Docs.** The design document's runtime section has a "Hosted mode (trial)" paragraph covering settings, the connector address `https://<domain>/mcp`, local Docker use, push-to-deploy and the trial's limits. The command's package comment names `-hosted`.

## Why it matters

Claude in claude.ai, on the web or a phone, can connect to the playmat as a custom connector and use every tool. It can also hand the player a link to a live board that follows its moves and takes theirs, with no desktop involved. This is the hosted-playmat epic's first, open, owner-only trial. It answers the epic's go/no-go question, whether claude.ai can drive the hosted board, before sign-in and per-user games are built on top. The public-address setting added here is the one value later specs (google-login) reuse. The desktop setup (Claude Code and Claude Desktop) behaves exactly as before.

**Trial limits:** no login, one shared game for everyone, and games and the card cache are lost on every deploy or restart.

## Deviations from the plan

- **The owner's setup task is deferred.** "Create the App Platform app and its domain" is deferred until after this branch is merged to `main`, by the user's decision: App Platform builds from `main`, so the app cannot be created first. The owner's steps:
  1. replace the placeholder domain in `.do/app.yaml` and push;
  2. authorise GitHub and run `doctl apps create --spec .do/app.yaml`;
  3. add the Cloudflare CNAME, DNS-only until the certificate is issued, then proxied with Full (strict);
  4. check `/` and `/mcp` on the domain.
  
  The claude.ai connector go/no-go check follows, as set out in the test plan.
- **Spec validation is unchecked.** The "passes App Platform's spec validation" criterion was checked only against DigitalOcean's app-spec reference, since `doctl` and an API token weren't available. `doctl apps create` in the owner's step 2 validates it.
- `hostedPublicURL` also rejects user info, which the plan didn't name.
- `runHosted` waits for `http.Server.Shutdown` before returning.
- A `pingTimeout` variable sits beside `pingInterval`, so the test for an unresponsive board runs in under a second.
- `.do/app.yaml` declares an explicit ingress rule.
- `.dockerignore` also excludes `.claude` and `.agents`.
- The trial limits are stated in the `.do/app.yaml` header as well as the design document.
