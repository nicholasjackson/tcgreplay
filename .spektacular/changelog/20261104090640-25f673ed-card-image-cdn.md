# Card images from the playmat's own CDN

## What was built

On the hosted playmat with the shared store (DigitalOcean Spaces) configured, the board now loads card images from the bucket's CDN instead of from TCGdex. The playmat copies each image the board shows into the bucket, byte for byte, the first time the image is shown, and points boards at the copy from then on. The card endpoint tells the board where to load each image from and which address to fall back to. Elsewhere (desktop, daemon, dev, offline, and hosted without the shared store) images load from TCGdex exactly as before.

- **Card endpoint.** `/api/card` has an optional image source (`webui.Server.Images`). With one set, a card's `image` is the address the source gives (the CDN copy). A new `image_fallback` field carries the TCGdex address whenever the two differ. With none set, the answer is unchanged.
- **Board.** The card on the mat, the zoom and the dialog preview each load `image`, then switch once to `image_fallback` if that fails. Only after both fail do they show the text stand-in or Energy token, as before. A Playwright spec covers this in the phone, tablet and desktop profiles.
- **Spaces client.** It gained `List` (signed ListObjectsV2, one page at a time) and `Config.PublicBase()`: `https://<bucket>.<region>.cdn.digitaloceanspaces.com` for a DigitalOcean endpoint, otherwise `<endpoint>/<bucket>`. The `spacestest` stand-in now answers listings with paging, and serves public-read objects to unsigned requests while refusing private and missing ones.
- **Image cache (`cards.ImageCache`).**
  - Answering: it answers from memory and never blocks. A known copy gets its CDN address with the TCGdex fallback. Anything else gets the TCGdex address and is queued for a background copy.
  - Copying: two workers fetch `low.webp` and `high.webp` from TCGdex and put them under `images/<TCGdex path>/` as public `image/webp` objects with `Cache-Control: public, max-age=604800`. Only `https://assets.tcgdex.net/` art is ever copied.
  - Start-up: it lists `images/` so copies survive restarts. It never deletes an object and never writes over one already in the bucket. When the start-up listing failed, it checks each image's own prefix before copying.
  - Outages: shared-store failures follow the card cache's breaker (3 s per request, skipped for 1 minute, logged once at start and once at end). Requests are serialised so an outage costs one attempt per window. An image TCGdex fails to serve waits 5 minutes before it is tried again.
  - Counts: every hour with activity it logs `card images: last hour A from the shared store, B from the card source (P% shared), K copied`.
- **Breaker.** The tiered card store's breaker was factored into a shared unexported type, with no change to its behaviour or its log text.
- **Hosted wiring.** `hostedCardDB` builds the image cache from the same Spaces client, only when the four settings are complete and the playmat is online. It logs the public image address, and `runHosted` runs the cache in the background. A new `hostedBoard` helper gives each account's board the cache.
- **Docs.** `.do/app.yaml`, the `Dockerfile` comment and the design document's hosted section describe the copies, the fallback and the hourly line. A new operator setup step covers enabling the bucket's CDN.
- **Knowledge.** The repo-tier entries `gotchas/tcgdex-cache-never-expires.md` and `gotchas/board-card-info-per-page-load.md` were updated.

## Why it matters

Hosted players get card art from the playmat's own delivery address, and TCGdex is asked for each image only once. That cuts load on the card source and makes the board's art independent of TCGdex's availability once copied. An image without a copy still shows at once, and a broken CDN falls back to TCGdex, so players never lose art. The hourly count line gives the operator the measure for the 95 % success metric.

## Deviations from the plan

- **Started before a dependency was implemented.** Implementation started before `20261104082020-109dceb1-tcgdex-spaces-cache` was implemented. It was in progress (9/10 tasks complete): all its code was merged, and only its human bucket-creation task was open.
- **Start-up listing and serialised shared requests moved into "Copy card images…".** The goal check required copies to survive restarts and an outage to cost one attempt even with both workers busy. So the start-up listing was implemented in "Copy card images…" rather than "Find existing copies…", and all shared-store requests are serialised by one mutex. "Find existing copies…" then added only the hourly count and fuller listing tests.
- **Copies are never written over.** The plan accepted re-uploading over existing objects after a failed start-up listing. The implementation instead never writes over any object in the bucket. It remembers half copies from the listing, checks each image's own prefix when the listing did not complete, puts only missing files, and remembers each file it has put.
- **Board.** Card.svelte now resets its image stage when the card shown changes. The old `broken` flag never reset.
- **Hosted wiring.** Board construction was factored into `hostedBoard` so it can be tested without signing in.
- **Docs.** The CDN setup is a new operator step 7, not part of step 6.
- **Naming.** The image path helper is `imageRel`, since `relPath` already existed.
- **Human task outstanding.** "Enable the CDN on the Spaces bucket" was not done. It needs the DigitalOcean control panel and was skipped after the goal check, so it is unticked and outstanding for the operator. Its checks, and the rest of the real-service checks (real CDN end to end, card data private, fallback with the CDN blocked, no shared store, restart keeps copies, iOS Safari, and the week-long 95 % measure), are in the test plan. Until the CDN is enabled, hosted boards' CDN addresses fail and fall back to TCGdex, so players see no difference.
