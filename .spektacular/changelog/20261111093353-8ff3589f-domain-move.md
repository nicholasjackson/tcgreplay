# Domain move: tcgreplay.app

## What was built

The hosted playmat moved from its borrowed address, tcgreplay.demo.gs, to its own domain, **tcgreplay.app**. That is now the single address the website, board, assistant connection and Google sign-in use and show. Players still on the old address are not stranded.

- **One address, one setting.** The server already derived every address it hands out from `TCGREPLAY_PUBLIC_URL`: sign-in issuer and metadata, board links, and the board's allowed origin. That setting is now `https://tcgreplay.app` in `.do/app.yaml`, with tcgreplay.app as the PRIMARY domain and tcgreplay.demo.gs as an ALIAS.
- **The website reads the address from the same setting.** `site/src/lib/facts.ts` no longer hard-codes the address. It reads `TCGREPLAY_PUBLIC_URL` from `.do/app.yaml`. The site build fails with a message naming the problem if the value is missing, is a platform placeholder, has a path, trailing slash, query or fragment, is not https, or does not match the PRIMARY domain.
- **Docs and README name tcgreplay.app.** This covers the claude.ai, ChatGPT and Claude Code steps, the Claude Code command, the example board link, the limits page and the README. The connecting page has one marked note (`data-moved-note`) telling players whose connector still points at the old address to remove it and reconnect at `https://tcgreplay.app/mcp`. A whole-site browser test fails the build if any built page or the README names `demo.gs` outside that note, or names `www.tcgreplay.app` anywhere.
- **A moved answer for old assistant connections.** The new `mcpserver.Moved` receiving middleware wraps a second instance of the playmat's MCP server. That instance has no game behind it and no sign-in. It lists the real tools and guide prompts, so an assistant that cached the old tool list still reaches the message. Its `initialize` instructions, every tool call (as an error result; the tool never runs) and every prompt say: "The tcgreplay playmat has moved to a new address. This connection no longer works: remove it, then add the playmat again at https://tcgreplay.app/mcp and sign in."
- **A moved-host guard in the hosted playmat.** The new setting `-moved-from` / `TCGREPLAY_MOVED_FROM` lists old host names (set to `tcgreplay.demo.gs` in `.do/app.yaml`).
  - **Start-up:** a malformed entry, or the public host itself, stops hosted mode from starting. The start-up log names the moved hosts.
  - **On a moved host:** `/mcp` gets the moved answer without sign-in, and a stale token is ignored. Every other path gets a permanent redirect (301 for GET/HEAD, 308 otherwise) to the same path and query on tcgreplay.app, so the old address never serves sign-in, metadata or the board.
  - **On any other host:** requests reach the router unchanged.
  - **Host handling:** the request host is only compared against the configured list. Every address sent still comes from the public URL.
- **Maintainer runbook.** `docs/domain-move.md` gives nine ordered steps, each with a Check. The order keeps sign-in working throughout:
  1. Google OAuth client.
  2. Consent screen.
  3. Attach tcgreplay.app in App Platform.
  4. Cloudflare DNS and certificate for tcgreplay.app (proxied, no `www`).
  5. The proxied demo.gs record.
  6. `doctl apps update` with the app spec.
  7. Narrow the demo.gs Cloudflare redirect rule to leave `/mcp` alone.
  8. End-to-end checks in each assistant.
  9. Remove the old Google callback.

  A retirement section removes the old address by configuration alone. The design document now names tcgreplay.app, describes the moved-host behaviour, and states that the request host is never used to build an address, only compared against configured hosts.

## Why it matters

The ChatGPT listing, the docs and the legal pages in the public launch all name the playmat's address, and a published ChatGPT plugin cannot change it later. So the move comes first in the launch. The old address forwards pages and tells an old assistant connection, in the conversation, where to reconnect, instead of failing with a bare error or a confusing re-sign-in. Retiring it later needs configuration only, with no release.

## Deviations from the plan

- `.do/app.yaml` already carried the public address, domains and comments (committed on main before implementation), so the first task only confirmed them. The moved-host setting and its comments were added later.
- `internal/mcpserver/server.go`'s `InitializedHandler` now also returns early when the server has no game manager. Without it, the moved instance panicked on `notifications/initialized`.
- The moved MCP handler is built in `runHosted` rather than returned from `newHosted`. The hosted test helper (`serveHosted` in `cmd/tcgreplay/cardsets_test.go`) routes through the guard so every hosted test covers the real wiring.
- The whole-site scan also asserts that exactly one move note exists across the site.
- The runbook has nine steps rather than seven. A goal-check retry moved "attach the domain in App Platform" ahead of DNS and the app-spec apply after DNS, so each step's check can show its result in order. The retirement section notes that committing an `.do/app.yaml` edit to `main` also runs the deploy workflow (a redeploy of the same code).
- **Human task "Carry out the console steps and put the move live":** accepted as a shortfall, with no criteria ticked. The maintainer confirmed "The domain is already live", and live probes agree for the new address. The rest waits for the merge: applying `TCGREPLAY_MOVED_FROM` with `doctl apps update`, narrowing the Cloudflare rule to leave `/mcp`, the consent-screen URLs, the live checks, and removing the old Google callback. These are listed in the test plan. Until then, `https://tcgreplay.demo.gs/mcp` is still redirected by Cloudflare.
