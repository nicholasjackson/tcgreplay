# Google sign-in for the hosted playmat

## What was built

The hosted playmat (`tcgreplay -hosted`, live at https://tcgreplay.demo.gs) now needs a Google account for everything. Claude Code and Claude Desktop, which run the playmat locally, are unchanged and never ask for sign-in.

- **Connector sign-in.** The playmat is its own small OAuth sign-in service for MCP clients, and it hands the login itself to Google. An anonymous request to `/mcp` gets 401 with a pointer to the protected-resource metadata. claude.ai then reads the playmat's sign-in metadata, registers itself (Dynamic Client Registration, restricted to Claude's callbacks and loopback addresses) and sends the user through Google's account chooser. It then exchanges a one-time code, with S256 PKCE, for an access token that lasts an hour and a refresh token that lasts until a restart and is replaced on every use. The official MCP Go SDK protects `/mcp` (`auth.RequireBearerToken`) and binds each MCP session to the Google account.
- **Board sign-in.** A signed-out board page goes through Google and returns to the page asked for. A signed-out live connection or card lookup is refused. The board header shows the account and a Sign out button. Signing out ends that browser's board session and closes its live connections at once; it does not disconnect the connector. A browser that connected claude.ai is already signed in to the board.
- **Signed in until restart.** Everything about sign-in lives in process memory. A restart or redeploy signs everyone out: the board sends the user back to Google, and claude.ai's next refresh gets `invalid_client`, its signal to register and sign in again.
- **Limits.** One per-account allowance (default 300 requests a minute, `0` = off) counts MCP requests, board actions and card lookups. Over it, Claude gets a tool error naming the limit, the board shows the same message, and a card lookup gets 429. A cap on signed-in accounts (default 10, `0` = off) shows a new account a "tcgreplay is busy" page, whichever way it signs in.
- **Settings and deployment.** The new settings are `TCGREPLAY_GOOGLE_CLIENT_ID` (or `-google-client-id`), `TCGREPLAY_GOOGLE_CLIENT_SECRET` (environment only), `TCGREPLAY_RATE_LIMIT` (or `-rate-limit`) and `TCGREPLAY_MAX_USERS` (or `-max-users`). Hosted mode refuses to start without the credentials. A new unauthenticated `/healthz` is the platform health check. `.do/app.yaml`, the Dockerfile notes and `make docker-run` carry the new settings.
- **Owner setup.** The owner created a Google Cloud project `tcgreplay` with a published (In production) consent screen and a Web application client for `https://tcgreplay.demo.gs/auth/google/callback` and `http://localhost:8080/auth/google/callback`, and set the two credentials in the App Platform console. Cloudflare needed no change.
- **Docs.** The design document describes sign-in, sign-out, restarts, the limits, every setting and the one-time operator setup.

## Why it matters

The hosted trial was open to anyone with the address. Sign-in keeps anonymous traffic out and protects the owner's server from abuse. It also gives the next spec (per-user games) a signed-in account on every request, on the board's request context and as the MCP token's user, to key games on.

## Deviations from the plan

- **Task order.** The Milestone 2 and 3 tasks were implemented before the human Google and App Platform setup task, as the epic orchestrator directed.
- **Open checks.** Two of that task's criteria wait for the deployed app and are in the test plan: that the deployed app starts after a redeploy, and that the sign-in endpoints are reachable without a Cloudflare challenge.
- **Health check.** App Platform's health check is still `/` until the owner switches it to `/healthz` after this deploys.
- **Test hooks.** The clock and HTTP client are exported `Config` fields (`Now`, `HTTPClient`). `hostedAuth` takes Google's endpoints as an argument, so the hosted tests wire exactly as production does with a fake Google.
- **Test helpers.** The helpers in `internal/hostauth/hostauthtest` take the public address and the test server address separately, aliasing one to the other.
- **User cap.** The cap is enforced inside the store's session creation, atomically, rather than as a separate admit step. An authorization code not yet exchanged holds its account's place. Refresh rotation and code exchange pass the count straight on. This closes two ways past the cap that testing found.
- **Token requests.** A token request with no `grant_type` gets `400 invalid_request`.
- **Signed-out non-GET requests.** A signed-out non-GET board request is refused with 401 rather than redirected.
- **Sign out on the board.** The board client tracks a sign-out in progress, so the live connection the sign-out closes does not bounce the user straight back to Google.
- **Test race fix.** The hosted tests' subprocess helper now buffers stderr under a mutex. This fixed a data race found under `-race`.
