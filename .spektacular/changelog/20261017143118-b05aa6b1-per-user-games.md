# Per-account games on the hosted playmat

## What was built

The hosted playmat (`tcgreplay -hosted`, deployed at tcgreplay.demo.gs) now gives every signed-in Google account its own game. Before, there was one shared game for everyone.

- **One game per account.** A new hosted-only registry (`internal/usergames`) holds, for each account, its own game manager and its own board server. They are created the first time the account is seen and kept in memory only. The board handle is a stable, opaque tag derived from the Google account id.
- **Claude acts on the caller's own game.** The MCP tool server gained an optional per-call resolver. In hosted mode every tool call looks up the caller's account from its access token and acts on that account's game. On the desktop the resolver is unset and every tool behaves exactly as before. Game-opening results (`import_log`, `new_game`, `set_opponent_deck`) carry the caller's own board link, `<public URL>/?board=<handle>`, instead of the shared root.
- **Owner-only boards.** The hosted board's front door sends each signed-in browser to its own account's board server, so a tab only ever shows, and gets live updates for, its owner's game. A link that names another account's board shows a "Not your game" page (403) with nothing of the game and a Sign out button. Signed-out visitors are sent through Google sign-in first. `/` with no handle opens one's own board.
- **Own name.** When a game doesn't name the player's side, the hosted board labels it with the signed-in account's name (the email before the `@`) instead of "You".
- **Idle games expire.** A new setting, `-idle-timeout` / `TCGREPLAY_IDLE_TIMEOUT` (default 60 minutes, `0` never; an invalid value stops start-up), sets how long a game may go without activity. Activity is a tool call, a board move or a board page load; an open tab does not count. Expiry is checked on every lookup and by a background sweep.
  - An expired game is dropped from memory.
  - Every tool call or board action that needs it says the game expired and asks for its saved record to be imported again.
  - An open board shows the same notice at once.
  - Importing the record brings the game back.
  - Accounts without a place and without activity for a day are forgotten.
- **Places under the user cap.** `TCGREPLAY_MAX_USERS` (still default 10, `0` off) now counts places, kept by the registry; the sign-in service asks it at every Google sign-in through a small `Places` interface. A place is taken at sign-in or at an account's first action after losing one. It is freed when the account's game goes idle, when its last sign-in ends, or on restart. So once the server is full, a new account can get in as soon as someone else's game expires. There is still exactly one limit, with the same "tcgreplay is busy" page.
- **Docs and app definition.** The design document describes per-account games, board links, the idle drop and its setting, places, and why the service must stay at one instance. `.do/app.yaml` declares `TCGREPLAY_IDLE_TIMEOUT` and says why `instance_count` must stay 1. The owner added `TCGREPLAY_IDLE_TIMEOUT=60m` in the App Platform console.
- **Also fixed:** the board's update hub kept a reference to every game it had ever shown, so replaced games were never freed. It now keeps only the current game, on the desktop too.

The desktop (Claude Desktop and Claude Code) is unchanged: one game, no accounts, no idle drop, no board-link handle.

## Why it matters

Several people can now share one hosted server without seeing or changing each other's boards. All of an account's claude.ai conversations, board tabs and devices share that account's one game, and board links open only for their owner. Clearing idle games and freeing their places keeps the trial server serving everyone in bounded memory.

## Deviations from the plan

- The landed google-login code kept its user cap in the sign-in store's session creation, not in a separate `admit` function, and its cap tests lived in `cap_test.go` and `hosted_cap_test.go`. The cap was moved out of there, as the plan's open assumptions allowed. `TestCapStore` and `TestCapZeroIsOff` were replaced by equivalent tests against a fake `Places`.
- Idle expiry runs while the registry's lock is held, and the sign-in service tells the registry about a last sign-out with its own lock held. Both are safe because neither managers, board hubs nor the registry ever call back up that chain; the lock order is documented on the registry. Releasing the lock first, as the plan suggested, would have let a sweep drop a game an action had just started.
- `Current()`'s error after expiry is the notice text itself (matching `ErrExpired`), with no "game expired:" prefix.
- `hostauth.WithAccount` was exported for wiring and tests. `newHosted` now builds the registry, the sign-in service and the MCP server together.
- An invalid `TCGREPLAY_IDLE_TIMEOUT` is reported only when hosted mode starts, so the desktop never fails on it, and an explicit flag overrides it.
- The deployed app was created by hand in the App Platform console, not from `.do/app.yaml`. The idle setting was therefore added in the console as an App-Level variable rather than with `doctl apps update --spec`, which would have needed the encrypted Google credentials re-entered. The checks of the single-container setting and of the start-up log line wait until after the merge deploys, and are in the test plan.
