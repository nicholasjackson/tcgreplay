# Coaching guides served by the playmat

## What was built

The playmat's six coaching workflows are now **guides** compiled into the binary, served to any connected assistant by the playmat itself, hosted and desktop alike. The six are importing a game, building the opponent's likely deck, reviewing a game, replay drills, the pre-move checklist and numbers drills. Before this change they were Agent Skills that each player had to install with `tcgreplay install` or upload by hand.

- **Guides package.** The six skill files moved (with history) from `skills/tcg-*/SKILL.md` to `internal/guides/<name>.md` and were renamed `import-game`, `opponent-deck`, `review-game`, `replay-drill`, `before-you-move` and `numbers-drill`. Each now has a single-line "use when" description. Wording changed only where the text named a skill: guides now refer to each other as "the `<name>` guide". `internal/guides` embeds them and lists them in a fixed order, and reading an unknown name gives an error listing the six.
- **`guide` tool.** With no name it lists the six guides with their "use when" lines. With a name it returns that guide's full text. It does not bind to a game, so on the hosted playmat it never takes one of the limited places and works even when game calls are refused as busy.
- **Server prompts.** Each guide is also an MCP prompt, so clients that show prompts as commands (such as Claude Code) can start a workflow directly. A prompt gives exactly the text the `guide` tool returns.
- **Connect instructions.** The instructions sent on connect end with a short block generated from the guide list: one line saying to read a guide before starting its workflow, then one line per guide. On hosted, the board-link line follows it.
- **Install command removed.** `tcgreplay install` and its tests are gone. The binary now refuses any leftover command-line word with `unknown command "<word>"` (exit 2) instead of silently starting the shim. Its help mentions neither install nor skills.
- **Checks.** The skills' text checks moved to the guides' tests: format, no "Claude" or "Nic ", no removed tools, turn numbering and seat-qualified branch names. New checks require that no guide says "skill", that cross-references resolve, that descriptions are single short lines, and that every tool or argument name a guide mentions exists on the live server. Integration tests prove the hosted and desktop playmats serve identical guides, prompts and guide instructions.
- **Packaging and docs.** `.dockerignore` excludes the whole `skills` folder, which now holds only Spektacular's own skills, while `internal/guides` stays in the build. The design notes describe guides instead of skills and the install command. The repo's *Skill text and packaging* convention now names the guides, with the user's confirmation.

## Why it matters

Any assistant connected to the playmat learns the coaching workflows from the playmat, with nothing installed or uploaded on the player's side. Because the guides ship in the binary, they always match that build's tools. A playmat update that changes a workflow reaches every client on its next connection, instead of leaving stale skill copies behind.

## Deviations from the plan

- The plan named a `text(...)` result helper in the MCP server that does not exist. The unknown-guide error result is built inline, as the server's other tool errors are. `add`'s doc comment now says only game tools go through it.
- The hosted "busy" scenario test reads a guide partway through an account's idle window. This also proves that reading a guide is not game activity.
- The knowledge convention kept its existing path rather than moving to a new one, at the user's choice.

Otherwise none. Skill copies already installed on players' machines or uploaded to claude.ai are untouched; players delete them by hand.
