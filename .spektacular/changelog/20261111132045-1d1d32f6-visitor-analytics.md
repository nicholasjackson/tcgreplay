# Visitor analytics: cookieless counting of website and board visits

## What was built

The hosted playmat can now count visits to the public website and to the board with Cloudflare Web Analytics. It does this without cookies, without browser storage and without a consent banner.

- **One integration, added at serve time.** A new package, `internal/webanalytics`, owns everything about the integration:
  - Cloudflare's manual beacon tag, with single-page-app tracking off (`"spa":false`);
  - a check on the site token (16 to 64 letters and digits);
  - the decision whether counting is on, with a one-line status for the start-up log that never shows the token;
  - an HTTP wrapper that adds the tag before `</body>` of a successful `GET` HTML page, for the public host only. Redirects, errors, `HEAD`, range responses, assets and anything not HTML pass through byte for byte.
- **Hosted mode wraps only two routes.** It reads a new setting, `TCGREPLAY_WEB_ANALYTICS_TOKEN` (flag `-web-analytics-token`), and wraps only the website mount and the `GET /board` page route. Sign-in, admin, MCP, the board's files and live connection, and the "Not your game" and refusal pages are never counted. A signed-out `/board` load still goes straight to sign-in.
- **Counting is on only when all of these hold:**
  - the token is set;
  - the token is well formed;
  - the playmat's own embedded privacy page carries the visitor-counting marker (`data-retention="visits"`, checked by `site.DescribesVisitorCounting`);
  - the request is for the public host from `TCGREPLAY_PUBLIC_URL`, ignoring case and port.

  Otherwise the playmat starts as before and its log says why counting is off. Local runs, the desktop app and the default test servers never count.
- **A board session is one page view.** Single-page-app tracking is off, so moving around the board (zooms, branch switches, the touch action sheet's history entries) never counts as another page view. In the dashboard, a board session is a page view of `/board`.
- **Operations.** The setting is declared without a value in `.do/app.yaml` and listed in the Dockerfile's settings notes. The design doc gained:
  - a "Visitor counting" section;
  - a settings-table row;
  - an operator step: set the token only once the privacy page is live, and clear it to stop counting.

  `make docker-run` deliberately does not pass the token.
- **Browser suites that never contact Cloudflare.** The website and board test servers gained an opt-in `-analytics-token`. Each browser suite runs a second server with it. New `analytics.spec.js` files route every other-host request to a stub or an abort, and show:
  - one beacon per page, with `spa:false`;
  - nothing else fetched from another host;
  - no cookies, and no storage beyond the board's four settings;
  - no second beacon while moving around the board;
  - with the beacon blocked, every page and the board still work, with no error.

  The site suite's existing "nothing from other hosts" check now names the no-token run and also checks that no page carries a beacon.

## Why it matters

Once TCG Replay launches publicly, the maintainer needs to know whether anyone uses it. The dashboard answers how many visits there are, which pages people read, where visitors come from and what devices they use. No visitor is identified, and nothing is stored in their browser. Counting cannot start before the privacy page describes it, because the binary checks its own privacy page.

## Deviations from the plan

- **The switch-on is deferred to the maintainer.** The human task "Switch visitor counting on for tcgreplay.app" was not done. It was skipped and deferred to the maintainer: live switch-on after deploy, per the user. The steps are in the implementation test plan:
  1. check the privacy page is live;
  2. check the start-up log says counting is off;
  3. create the Cloudflare site with the manual snippet and automatic injection off;
  4. set the token;
  5. check the log says `visitor analytics: on for tcgreplay.app` and that the page carries one beacon.

  Until then the deployed code counts nothing.
- **Test wiring follows the domain move.** The hosted test wiring sits in `serveHosted`, inside the domain move's `movedGuard`, where the hosted handler is now built, rather than in `startHostedWith`.
- **Small, safe additions to the wrapper.** It also passes through content-encoded HTML, and it drops `Accept-Ranges` from pages it alters.
- **The crawl blocks Cloudflare first.** The site crawl gained a `prepare(context)` hook, so the analytics crawl blocks Cloudflare before it loads any page.
- **One catch-all route in the browser suites.** They route every other host through one catch-all rather than two Cloudflare-only routes.
- **The action sheet is checked on tablets too.** It is exercised on the tablet profile as well as the phone, because both push history entries.
- **Docs.** The design doc's old operator step 9 is now step 10.
